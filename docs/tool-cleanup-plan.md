# QQ 工具与整理决定

本文维护工具清单、保留理由与整理边界；完成状态和后续工作统一见[开发进度与计划](progress.md#当前进度与下一步)。

当前定义了 18 个 QQ 工具，全部有对应实现。文字发送统一为 qq_send，引用作为可选参数；各工具按当前聊天、功能开关和运行条件提供。无需为了减少工具数量，把不同操作合成一个大工具。

整理后的工具覆盖文字发送、跨聊天权限与目标记账、按条件提供的功能分组、普通图片收藏和统一参考资料；人设工具名检查及重复旧入口退出。本文说明这些决定与约束，参考资料的使用说明见[参考资料](knowledge.md)。

后续新增和修改工具遵循[工具设计规范](tool-design.md)：固定规则放在工具说明中，返回保留简短的本次数据、状态和必要位置，不重复使用教程。

## 已确认的决定

已经确认：

- 已删除 `TOOL_TOKENS`、`personaLeaks()`、启动和重载时的两处人设警告，以及对应测试。它们原先只检查人设是否包含工具名，不负责注册或授权；用户可以在人设里描述工具使用偏好。
- `qq_memo` 最终由统一资料检索替代，不再长期保留一套共享记忆或通用共享写文件功能。
- 查梗与角色资料共用资料检索入口，由程序建立索引，不要求普通用户自行准备特定结构的 SQLite 数据库。该入口已实现，来源必须显式选入并指定范围。
- `qq_images` 历史取图继续不受实时成员图片屏蔽限制。不能借这次整理改变已确认的行为。
- 保留商城表情自动登记：收到可用的 `mface` 后保存重发所需的 ID、名称等信息，不调用模型决定是否登记，也不下载图片。自动登记不代表必须发送。
- 商城表情登记与普通图片收藏分开说明。`faceCollectHint` 只描述普通图片收藏，不控制商城表情登记；不能继续声称留空就“什么都不收藏”。
- 工具按功能分组：基础聊天能力默认提供，QQ 互动和表情包使用默认开启，合成语音和发布空间默认关闭，资料查询配置后提供。具体配置与范围见下表。

- 跨聊天发送仅允许授权账号私聊发起，当前聊天和目标聊天均须在允许服务的范围内。
- 普通图片收藏：`faceCollectHint` 留空时不自动收藏，但用户明确要求时仍可收藏；填写规则后，允许模型按规则收藏。商城表情自动登记不受该字段影响。

旧 qq_reply 已移除，未保留重复入口。后续若出现现有决定无法覆盖的实际问题，再单独确认；尚未实现的设计不能写成当前已有行为。

## 现有工具与保留理由

下表完整列出 18 个工具。归为一行表示用途相关，不表示必须合并。

| 工具 | 当前用途 | 整理安排 |
| --- | --- | --- |
| `qq_memory` | 查询、修改当前事项、长期事实和已确认词义，查看版本 | 保留。自动记忆维护不能替代用户主动查询和更正 |
| `qq_history` | 查询聊天收发原文、翻页、续读长消息 | 保留。原文与记忆摘要不是同一份数据 |
| `qq_images` | 根据消息 ID 从协议端重新获取图片并缓存，返回本地路径 | 保留。文字历史查询不等于取回图片；远端链接失效时仍可能失败 |
| `qq_send` | 普通文字或引用发送；还能指定其他聊天 | 已统一；可选 message_id 指定引用，省略时普通发送 |
| `qq_send_image`、`qq_send_file` | 发送图片气泡、上传可下载文件 | 都保留。协议操作和接收者看到的结果不同 |
| `qq_recall` | 撤回消息，默认撤回最近发送的一条 | 保留。需要修正已发消息时有独立用途 |
| `qq_poke`、`qq_react`、`qq_like`、`qq_face` | 戳一戳、消息表态、名片点赞、发送内置表情 | 都有独立用途；随默认开启的 QQ 互动功能提供 |
| `qq_mface`、`qq_faces`、`qq_keep_face` | 发送表情包、查收藏、收藏本地图片 | 三者不重复；查找和发送由表情包使用开关控制，普通图片收藏按单独规则处理 |
| `qq_send_voice` | 用 Windows SAPI 合成并发送语音 | 保留为可选能力；当前实现只能在 Windows 使用 |
| `qq_qzone_send` | 发布 QQ 空间说说 | 保留为可选能力；保持授权账号私聊、确认后发布、限制尝试次数和不自动重发 |
| `qq_search` | 搜索参考资料，按命中位置读取段落、章节或全文 | 统一文件、目录、可选角色包和旧梗词库导入；原文不改写，大段可续读，不写资料 |
| `qq_sources` | 明确添加、更新、移除资料来源及可见范围 | 仅授权账号私聊可用；设置页也有管理入口。原文件保留，不自动公开 |

普通模型正文已经由插件自动发送，但文字发送工具仍可用于引用某条消息、处理过程中发送消息，以及经授权向其他聊天发送。不能因为存在自动发送就直接删除全部文字发送工具。

`read_image` 来自宿主预设，不是 QQ 插件定义的工具；`[SILENT]` 是控制外发的标记，也不是工具。删除人设检查不会删除这些能力。

代码入口：[主要工具](../src/tools.js)、[语音与空间](../src/tools-extra.js)、[记忆](../src/memory-tools.js)、[聊天原文](../src/message-tools.js)、[参考资料](../src/knowledge-tools.js)。

## 工具开关与默认值

工具定义注册后，由宿主 tools.register 的 when 条件在每一步选择实际提供的列表；所有 QQ 工具仅向获准的 QQ 聊天提供，普通 Agent 不提供这些工具。执行端再次核对当前权限和开关，不依赖模型遵守提示词。qq_search 仅在当前聊天有可见来源时提供，qq_sources 仅向授权账号私聊提供。

| 功能 | 确定的默认值 | 范围 |
| --- | --- | --- |
| 基础聊天能力 | 提供，不另设总开关 | 文字、引用、图片、文件、撤回、聊天记录、历史取图和统一记忆；继续检查原有聊天访问权限 |
| QQ 互动 `qqInteractionEnabled` | 开 | 戳一戳、消息表态、名片点赞、内置表情 |
| 表情包使用 `stickerEnabled` | 开 | 查找和发送已有收藏；开启使用不代表允许自动收藏所有普通图片 |
| 合成语音 `voiceEnabled` | 关 | 用户主动开启；当前 Windows SAPI 实现只在 Windows 提供，声音名称留空仍表示使用系统默认声音 |
| 发布空间 `qzoneEnabled` | 关 | 用户主动开启；授权账号私聊、确认和发布次数限制继续有效 |
| 资料查询 | 配置后提供 | 统一资料检索；当前聊天有可见来源时提供，不增加模型调用 |

设置页“QQ 工具”提供四个分组开关、普通图片自动收藏规则；资料来源在“参考资料”分区独立管理。保存后，下一次主模型请求或工具续调重新选择工具；关闭后尚未开始执行的旧调用也会拒绝。语音合成和空间图片准备完成后还会复查；已经提交到协议端的操作不能撤销。宿主预设已有的工具限制继续生效，不重新挂载预设，也不改变普通 Agent 的工具。

不增加独立的“商城表情自动登记”开关，保留现有收集行为。表情包使用开关控制模型能否查找、发送收藏，不因关闭使用删除已有收藏，也不把它当成普通图片收藏的总开关。普通图片的收藏方式按下一节已确认的规则处理。

## 图片缓存与表情收藏

这三件事用途不同，设置和说明必须分开：

| 行为 | 何时发生、保存什么 | 后续处理 |
| --- | --- | --- |
| 图片缓存 | 普通图片下载后供模型查看，属于聊天媒体文件 | 按既有附件保护和清理规则管理；不能因为查看过就自动变成长期收藏 |
| 普通图片收藏 | 模型调用 `qq_keep_face`，把本地图片复制到收藏目录并登记名称，供以后作为表情包发送 | 用户明确要求时可收藏；自动收藏仅在填写规则后由模型按规则执行，留空不自动收藏 |
| 商城表情自动登记 | 处理可用 `mface` 时，由程序把表情 ID、表情包 ID、key、名称等信息写入收藏清单 | 保留现有行为，不经过模型筛选、不下载图片、不受 `faceCollectHint` 限制；由发送工具决定是否使用 |

普通图片与商城表情共用现有收藏清单，不为这次说明另建一套收藏库。收藏清单不是聊天记忆，也不表示模型已查看图片内容。商城表情保存了 ID，不保证协议端以后一定能成功重发，仍以实际工具结果为准。

`faceCollectHint` 默认空，设置页已有“普通图片自动收藏规则”。规则放在请求末尾状态区动态更新，不再随图片消息写入历史，避免旧规则影响后续收藏。商城表情登记不使用 qq_keep_face。

`qq_keep_face` 必须注明 mode：requested 表示用户明确要求；automatic 表示按配置自动收藏。automatic 在规则为空时由程序拒绝，requested 不受空规则限制。是否确有用户要求、图片是否符合文字规则仍由模型结合真实消息判断，程序不声称能客观识别语义。已有收藏不清空，缓存与收藏仍保存独立副本。

发图的频率限制与收藏分开。当前 `qq_mface` 和 `qq_send_image` 共用默认至少间隔 90 秒、每小时最多 6 张的限制；登记新表情不会自动发送，也不会因此消耗发送额度。

## 行为约束与检查范围

### 1. 文字发送入口

仅保留 qq_send，message_id 为可选引用参数，不提供时普通发送，不自动引用最近消息。普通回复仍直接输出正文。

引用前先查目标聊天 SQLite 的入站或已确认出站消息；未找到时通过 get_msg 核实目标群或私聊发言人。归属缺失、属于其他聊天、ID 无效或查询失败时不发送。异步查询后复查权限。引用发送沿用目标记账、结果未确认不记成功、当前聊天正文去重和跨聊天结果说明。

旧 qq_reply 不再注册，也不保留兼容别名。升级后新请求和恢复会话使用当前工具列表；升级前已生成但未执行的旧调用会报告工具不可用，不自动重放整轮。用户自定义人设若写死 qq_reply，应改用 qq_send 的 message_id。

### 2. 工具提供条件

- QQ 互动和表情包使用默认开启；合成语音和发布空间默认关闭。旧部署仅填写 voiceName 不代表启用语音，需要明确打开 voiceEnabled。
- qq_send_voice 还要求 Windows；声音名称留空使用系统默认声音。
- qq_qzone_send 还要求授权账号私聊，原确认要求、每日尝试限制和未知结果不重发继续有效。
- qq_search 统一搜索和读取明确选入的文件、目录和可选资料包；搜索返回预览和位置，读取支持段落、章节、全文及续读，不拆改原文长行。私有范围按机器人与聊天隔离，公共范围必须明确列出可访问聊天。
- 旧 qq_memo、qq_meme 已移除；旧目录和数据库保留，管理员通过资料入口显式选择迁移范围，不自动索引或公开。
- qq_keep_face 独立于表情包使用开关，保留明确收藏能力；qq_images 不受实时图片屏蔽扩展限制。

每步选择通过官方接口完成，执行端复查条件；不改写宿主组装结果、不修改宿主插件。工具列表变化可能影响提示缓存，system 的锁定与同步流程保持不变。

### 3. 跨聊天发送权限与目标记账

`qq_send` 和 `qq_send_voice` 共用目标解析与权限检查。省略 `to` 或显式指定当前聊天均按当前聊天处理，不额外要求授权身份；跨聊天发送仅允许授权账号私聊发起，当前聊天与目标均须允许访问。账号身份不符、目标格式无效或聊天未获准时，拒绝发送。

文字在内容检查后重新检查权限；语音还在合成结束、外发之前再次检查。合成期间撤销授权或关闭聊天，不会继续外发。协议调用失败或回执缺少有效消息 ID 时，不写成功的会话记录，不改变默认撤回目标；结果不明时不自动重发。文件上传的成功回执不要求消息 ID，沿用既有行为。

SQLite 按实际目标记录发送结果；目标存在活跃会话时，其历史、记忆发送记录和默认撤回目标也同步到该目标，不污染发起聊天。目标没有会话时只保存 SQLite 发送记录，不为记账新建或恢复 Agent。跨聊天发送不冒充目标聊天自身的主动轮交付，也不抑制发起聊天正常说明结果；当前聊天发送的正文去重行为继续保留。

已确认的规则如下：

- 普通聊天只能向当前聊天发送。
- 向其他聊天发送仅限授权账号私聊发起，当前聊天和目标聊天均须获准。
- 校验在工具执行代码中完成，不能只写在提示词里。
- 权限失败时不合成语音、不调用外发接口，也不记录为已发送。
- 向其他聊天发送后，发送记录归目标聊天；不能把内容或消息 ID 记为当前聊天收到的回复。

这项修复可以独立于工具合并进行，不必等资料检索完成。

`qq_images`、`qq_react`、`qq_recall` 等接收消息 ID 的工具，也应核对目标消息的聊天归属及允许操作的对象。此处是后续检查项，不表示已经证实它们存在同一个漏洞；历史取图不受实时图片屏蔽限制，也不等于允许读取其他聊天的图片。

### 4. 工具调整还涉及发送记录和提示词

发送工具不能只完成协议调用。合并或限制工具时，还需检查：

- 成功、失败和回执不明是否正确记账；不能无条件声称发送成功。
- 工具发言与正常正文是否重复发送；图片、文件、表情与纯互动是否沿用各自的回复规则。
- 未知结果不通过重新执行整轮模型自动重发，避免再次执行工具。
- 工具说明、固定规则、设置描述、启动日志与测试是否仍使用已删除的名字。

这些是调整时必须验证的行为，不是要求本轮顺带重写所有外发代码。

## 执行结果与长内容

戳一戳、表态、点赞、取图、发送、撤回和收藏执行失败时抛出错误，由宿主标记为工具失败，再让模型继续处理；不再用成功结果里的 `ok:false` 表达失败。空收藏、未匹配到名称和消息没有图片都是正常空结果。

外部操作区分三种异常：调用前未连接是“未发送”；协议明确拒绝是“协议拒绝”，有数字错误码时附带错误码；超时、发送后断线或缺少有效消息 ID 是“未确认”。未确认可能已经执行，程序不自动重试，也不写成功记账或消耗成功发送额度。详细异常留在日志，固定的核对和重试规则写在工具说明里。

文字、语音、图片、内置表情和商城表情发送都以有效消息 ID 确认，负数和零值同样有效；文件上传以协议操作成功回执确认。`qq_mface` 每次只尝试一次，不自动改用 CDN 发送。OneBot 连接关闭时结束未完成请求，结果保持未确认，不等超时后再冒充明确失败。

以下上限均计算完整 JSON，包含元数据和转义后的文字；不改变存储的原文：

| 工具 | 单次返回和续读 |
| --- | --- |
| `qq_faces` | 最多 50 个名称、12000 字符。`total` 包含全部收藏，`unnamed` 是无名称数，`matched` 是匹配的有名称条数；`partial`、`next` 明确表示还有内容。保持关键词，用 `next` 的 `offset`、`textOffset`、`snapshot` 续读，超长单个名称也可拼回完整内容 |
| `qq_memory` | 列表和历史返回概览，默认 20 条、最多 50 条及 12000 字符；每条文字最多预览 600 字符，`partial` 标记文字不全。完整正文和来源证据按 `id`、`version` 用 `action=read` 读取；具体字段见[记忆查询](memory-design.md#查询与版本读取) |
| `qq_history` | 最多 20 条、12000 字符。`partial` 与 `next` 标记局部结果；`next` 带 `seq/offset` 时先续读该条，带 `before` 时继续查较早消息。单条定位或长消息读完后，只要同一筛选范围内还有更早记录，就继续返回 `before`，不提前结束分页。保持原筛选条件；旧 `before` 和每条 `nextOffset` 仍可使用 |

收藏与记忆翻页携带内容指纹 `snapshot`；数据或筛选变化时返回工具错误 `STALE_PAGE`，从头查询，不把变化前后的位置混用。长文字按连续 UTF-16 位置读取，不在表情符号的代理对中间切开。

`qq_images` 每批最多下载四张图片。`total` 是该消息可取回的图片数，`failed` 列出本批下载失败的图片序号，`nextOffset` 用于取后续图片；部分取回用 `partial` 标记，全批下载失败或消息回执无正文则走失败通道。返回路径后不再重复要求打开图片，`read_image` 用法保留在工具说明中。历史取图仍不受实时成员图片屏蔽限制。

`qq_search` 返回命中、来源、位置及读取失败的来源信息，不再逐次附带免责声明或续读教程。收藏结果只返回是否新增和总数；限流只返回本次原因和等待时间。

## 验证标准

验证客观行为，不用“模型回复是否讨喜”作为通过标准：

- 删除人设检查后，包含工具名的人设能正常加载，启动和重载不再产生这类警告；现有提示词组装不变。
- 普通账号、授权账号、群聊和私聊的发送权限符合最终确认的规则；目标被禁用时不外发。
- 指定目标和引用消息同时出现时，不把其他聊天的消息 ID 当作当前目标的引用；校验失败无副作用。
- 当前聊天和跨聊天的文字、语音分别正确记账，沉默、失败和回执不明不冒充成功。
- 合并后普通发送与引用发送均可用，工具发言不与模型正文重复发送；旧入口按确认的迁移规则处理。
- 未配置资料库、不支持语音的平台、自动收藏规则留空等情况下，工具说明与实际可用性一致；是否提供工具按最终设计断言。
- 商城表情自动登记不调用模型、不下载图片，按 ID 去重，不受普通图片收藏规则影响；登记本身不触发发送、不消耗发送额度。
- 普通图片缓存不因查看自动变成收藏；明确收藏后保存独立副本。已有商城表情和图片收藏不因升级或关闭使用而丢失。
- 普通图片收藏规则留空时，不产生自动收藏，但用户明确要求收藏仍能成功；规则非空时，模型收到准确的筛选规则，不能把它扩展为收到所有图片就收藏。商城表情登记不参与这项判断。
- `qq_images` 仍能按原设计回查图片，成员实时图片屏蔽不会扩展到历史取图。
- 新建、恢复会话及工具续调的工具列表符合预期，不重复注册，不误改普通 Agent 的能力。

先跑改动对应的专项测试，再跑全套和 mock 端到端测试。mock 只能证明模拟路径；真实 DSH 预设更新、协议端支持和实际 QQ 发送需另外验证，不以未实测的行为作完成依据。

## 与已有设计的关系

- [项目整理记录](project-audit.md)：本文细化工具部分，资料检索的范围与已有决定一致，不重新引入已移除的阅读、文件信箱或定时群词扫描。
- [群消息设计](group-message-design.md)：继续使用已落地的消息存储、容量控制、处理位置和发送结果记录，不另建消息队列或聊天历史工具。
- [记忆设计](memory-design.md)：`qq_memory` 继续管理当前事项与长期记忆，资料检索不接管这项职责。
- [配置参考](configuration.md)：维护当前配置与实际行为，不能把待实现的设计写成已发布功能。

固定规则仍遵守已有 system 锁定和同步流程；动态状态仍在请求末尾提供，不因工具整理改变。工具列表本身也可能影响缓存；本次已用未修改的本地 rc.2 宿主验证每步选择及工具续调更新，不承诺动态开关完全不影响缓存，也未引入宿主补丁。
