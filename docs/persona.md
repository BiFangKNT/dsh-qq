# 人设、授权与称呼

插件默认是没有固定角色的普通助手。人设、账号授权和成员称呼分别配置，不互相推导。

| 配置 | 用途 |
| --- | --- |
| `persona` / `personaFile` | 机器人自己的名字、性格、语气和角色背景 |
| `ownerIds` | 授权账号名单，支持多个 QQ 号；供相关功能检查权限 |
| `memberLabels` | 按 QQ 号设置对该成员的称呼，群聊和私聊通用 |
| `directPrompt` / `groupPrompt` | 私聊和群聊的补充提示词 |

## 授权与称呼

```yaml
ownerIds: ['10001', '10002']
memberLabels:
  '10001': 爸爸
  '10003': 小林
```

这个例子中，10001 和 10002 都是授权账号，但只有 10001 使用「爸爸」这个称呼。10002 未设置称呼，按群名片、昵称或「你」称呼。10003 可以称为「小林」，但不会因此获得权限。

设置页分别提供「授权账号（QQ 号）」和「成员称呼」。添加授权账号不会自动继承其他人的称呼；删除授权也不会删除称呼。授权不影响消息处理顺序，不绕过群聊触发条件，也不能代替 `privateAllow`。

`ownerIds` 是部分工具的实际权限依据，例如私聊流水正文查询和 QQ 空间发布。通用本机工具是否可用还受宿主预设和工具实现约束；提示词中的提醒不能替代工具层的权限检查。

消息转录使用中性标记，例如：

```text
⟨成员 (10001) · 授权账号 · 称呼 "爸爸" 11-13 周五 13:05（下午）⟩ 你好
```

当前授权名单与称呼每次在末尾状态区提供，优先于旧消息里的历史标记；不因配置变化重写旧聊天。

### 旧配置迁移

旧 `ownerLabel` 已退出设置页。升级首次启动时，将其迁移到当时 `ownerIds` 中各账号的 `memberLabels`，保留已有的独立称呼，然后在插件的 `settings.json` 中保存结果并清空旧字段。新增账号不会在重启后再次继承旧称呼。

如果旧名单中已经有多个账号，迁移会保留它们原来的共用称呼。可在「成员称呼」里逐个修改或移除。没有显式配置过旧称呼的账号，使用默认的昵称、群名片或「你」。

## 人设与补充提示词

```yaml
persona: |
  你叫小满，是个住在电脑里的助手，语气轻松，喜欢简洁的表达。
```

人设描述机器人自己。对具体成员的专属称呼应配置在 `memberLabels`，避免人设中的「称对方为某某」被套用到所有人。

内置提示词只说明聊天、消息来源、时间、工具、记忆和隐私边界，不强制嘴硬、拒绝道歉、固定句末标点或禁止列表和代码。复杂问题可以按需要展开；事实和操作结果必须有依据。

system 中按顺序放入内置规则、私聊或群聊补充、人设。`personaInSystem: true` 表示人设由宿主系统提示提供，插件不再重复添加。

system 在新会话、成功压缩后同步；其他时候锁定。设置页修改相关提示词后可选择新建、压缩、强制同步或稍后同步。升级也不会自动改写已有会话的 system，要使用新规则需同步。强制同步保留历史，但可能影响提示缓存。

账号授权、称呼、当前事项、长期记忆和表情收藏属于当前数据，在末尾状态区更新，不追加旧快照，也不进入 compact。称呼或授权变化从下一次模型步骤生效，不需要同步 system。

## 图片、引用与沉默

- 图片按实际读取结果回答，不能读取时说明，不猜测。
- 引用内容是背景，结合当前发言判断对谁说话；引用别人也可能是在向机器人提问。
- 触发一次处理不代表需要回复每条背景消息。允许沉默的轮次可输出 `[SILENT]`，插件不会发送该标记。
- 主动发言、阅读、睡前提醒和夜间消息使用各自的简短说明，不编造对方当前在忙什么或是否已经睡觉。

群聊触发与分批实现安排见[消息调整方案](group-message-design.md)。记忆和 system 的实现约束见[开发说明](emotion-system-development.md)。

## 表情包

`faceCollectHint` 决定哪些普通图片可以主动收藏，留空时不主动收藏。商城表情仍可按工具说明使用 `qq_keep_face` 收藏。

当前收藏名称在末尾状态区提供，可用 `qq_faces` 查询、`qq_mface` 发送。按内容决定是否使用，一次一张，不要求每次回复都配图。`faceSendGapMs` 和 `faceSendMaxPerHour` 的限制仍由程序执行。

公开示例与测试使用虚构账号和角色，不将私人设定、真实账号或聊天案例写进内置规则。
