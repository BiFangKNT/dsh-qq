## 1. 可选功能及前置分类器

下列名称用于说明行为，实际字段和已实现情况见[开发进度](emotion-system-development.md)。分类器已经实现且默认关闭；未实现的情绪开关默认值仍待定，不因“可选”就推导为默认关闭。

| 参数 | 已明确的定义 | 来源/状态 |
| --- | --- | --- |
| 前置分类器开关 | 可选，默认关闭；关闭后按是否必须 @决定仅 @触发或合并普通新消息 | 已实现 |
| 分类任务 | 判断当前发言人是否正在对机器人说话 | 用户确认；不等同于识别情绪 |
| session 隔离 | 独立于主模型 session；分类对话、结论和推理不进入主模型上下文 | 用户确认；按群/私聊分别隔离的具体生命周期待实现定义 |
| 推理强度 | 默认 `low`，允许自定义 | 用户明确给定 |
| 模型/provider | 未定义是否允许独立选择，以及默认配置来源 | 接入时核实宿主能力 |
| 分类覆盖范围 | 启用范围内，每条新入站消息参与判断；账户和会话权限仍优先 | 用户要求每条新消息；群/私聊启用粒度待定义 |
| 分类上下文 | 需要支持指代、引用及连续对话判断；长度、保留期未定义 | 不能只凭单句无上下文就宣称完成需求 |
| 分类超时、并发和排队 | 未给数值；用于取消、卸载和资源控制 | 待实现定义；延迟与模型成本不是需求阻塞项 |
| 分类返回无法识别 | 严格解析后正则提取完整 `yes/no`；矛盾结果不采用；仍失败额外重试两次，最后按 `yes` 放行并记录 `fallback_yes` 警告日志 | 用户补充；合计最多三次请求，记录解析方式与次数 |
| 分类请求失败 | 网络、超时、配置错误仍区分于 `no`，保留源消息并可查错误；关闭或卸载不触发兜底 | 工程约束；不自动切换模型 |
| 无互动情绪变化开关 | 可选，控制长时间无人互动造成的情绪变化 | 按用户要求将“冷落/断联”机制拆清；具体配置名待定 |
| 等待回应冷落开关 | 可选，控制发出消息后等待某人回应的哀伤事件 | 用户确认可选；关闭不得继续触发此类事件 |
| 断联好感衰减开关 | 可选，控制按人计算的无交流衰减 | 用户确认可选；与其他两类规则分别列账 |

上述三个冷落/断联开关对应不同规则，不应只用一个“冷落阈值”同时驱动三者。它们不隐含关闭正常互动、六欲演化或其他好感日结。

## 2. 优先厘清：无互动、等待回应、长期断联

### 2.1 全局无互动导致情绪变化（原 FR-004）

| 参数/规则 | 原文已有定义 | 缺少或需澄清的定义 |
| --- | --- | --- |
| 作用指标 | 哀、怒的静息点 | 是否对两者使用相同曲线 |
| 计时起点 | 无互动时长 | 什么算有效互动；机器人自己发言是否刷新；群旁观消息是否刷新 |
| 开始漂移阈值 | 只说“长期” | 具体时长 |
| 漂移速率/曲线 | 只说“缓慢上抬” | 每单位时间变化量或函数 |
| 漂移上限 | 未给 | 相对初始静息点还是绝对值；与指标 100 上限的关系 |
| 恢复触发 | 有互动立即回落 | 回落的是静息点；当前情绪是否立即跳变，原文未说明 |
| 睡眠、停机、关闭功能 | 未给完整定义 | 哪些区间暂停累计；重启是否补算；重新开启从何时计时 |
| 与其他规则叠加 | 未给 | 是否与等待回应事件同时生效，如何记录来源 |

### 2.2 发出消息后等待回应（原 FR-022）

| 参数/规则 | 原文已有定义 | 缺少或需澄清的定义 |
| --- | --- | --- |
| 触发前提 | 她已发出消息，对方未回复 | 仅主动提问，还是所有发言；群消息中如何指定等待对象 |
| 等待起点 | 发出消息后 | 应以发送成功回执为起点；失败/仅生成未发出不构成等待 |
| 等待阈值 | 超过阈值才触发 | 具体时长 |
| 情绪方向 | 哀上升 | 基础增量、强度函数 |
| 等待越久影响越大 | 有上限 | 函数、上限数值、计量单位 |
| 每段等待次数 | 只计一次 | “只计一次”与“强度随等待增长”需要统一：在哪个时刻取强度，延迟 tick 如何避免结果不同 |
| 等待结束条件 | 对方回复 | 什么算回复；同人在另一会话发言是否结束；明确告别或拒绝是否结束 |
| 重复发言 | 未给 | 后发消息重置、合并还是新建等待；不能为每个分句创建一份惩罚 |
| 睡眠 | 不判定 | 暂停剩余计时还是取消本次等待，醒来是否继续 |
| 好感影响 | FR-026 明确求助未被回应者不因此扣分 | 等待事件是否参与交流质量扣分需统一；不能经间接链路违反该豁免 |
| 开关切换 | 新增为可选 | 关闭时取消或冻结在途等待；开启时不应补罚关闭期间 |

### 2.3 长期无交流的好感衰减（原 FR-019、附录 B）

| 参数/规则 | 原文已有定义 | 缺少或需澄清的定义 |
| --- | --- | --- |
| 无交流判定 | 一天完全没有交流 | 自然日的时区；单向发言、群内旁观、分类器 `no` 是否算交流 |
| 连续计扣上限 | 5 天，第 6 天起不再下降 | “连续”是否被任意交流重置；冷却结束后是否开启新一轮 |
| 每日基础扣分 | 未给 | 每天扣多少，是否按日相同 |
| 第 5 天额外扣分 | 第 5 天额外多降 | 额外数值；受哪些日限额约束 |
| 衰减下限 | 40 | 原本低于 40 时应不扣、不抬升；等于 40 时为零变化 |
| 冷却 | 10 天 | 从首次扣分、最后扣分还是周期结束开始；冷却与 5 天计扣如何共存 |
| 特殊关系 | 不衰减 | 特殊关系名单和优先级；不以管理员权限代替 |
| 接近两端的速度系数 | FR-018 给最低 0.25 | 衰减是否也乘该系数，未说明 |
| 与每日净变化上限关系 | 附录 B 给单日上限 5 | 衰减是否占该额度，先结互动还是先结衰减 |
| 停机补算 | 通用补算上限 6 小时，但这里按日 | 是否追扣停机天数；上限、冷却和日界线如何分段 |
| 可选开关 | 用户要求可选 | 关闭不影响互动加减分；开启不回算关闭期间的扣分 |

这三类规则都可实现。参数问题是定义尚不完整，不是行为需求不成立，也不需要用真人心理学证明其合理性。

## 6. 参数定义的完成条件

每个参数最终应有：含义、类型、单位、作用对象、默认值、合法范围、零值含义、开关关系、生效时刻、持久化规则和来源。未定值继续标注未定；开发排期与功能需求分开管理。

客观验证关注：边界值、计时重叠、跨日与时区、关闭后残留计时、重复计扣、发送失败误判、上限冲突、特殊关系豁免、消息不丢失和重启恢复。不会用“是否像真人”“够不够亲近”等主观评价决定逻辑验收是否通过。
