# 配置项速查

全部配置都写在 profile 的 `cordis.patch.yml` 里 `dsh-qq` 那一行的 `config:` 下面；也可以用 DSH 设置页里「QQ」那节点着改（详见 [README](../README.md#在-dsh-设置里调它)）。

> 一行 patch 是**整行替换、不是深合并**：后写的 `config` 会把前面的整块盖掉，所以改的时候把要保留的键一起写全。

## 连接

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `wsUrl` | 空 | NapCat 的 WebSocket 服务端地址，如 `ws://127.0.0.1:3001`。**留空就不连接**（不会偷偷去连 3001）；填好保存约 0.8 秒自动接上，不用重启 |
| `accessToken` | 空 | NapCat 那边设的 Token，留空就不带鉴权头 |
| `selfId` | 空 | 机器人 QQ 号。留空会自动 `get_login_info` 查 |
| `localApiPort` | `34569` | 独立设置服务的回环端口；`0` 关闭此服务，仍保留宿主路由。多实例使用不同端口，修改后重启宿主；设置页顶部可选择要连接的本地端口 |
| `reconnectMs` | `5000` | 断线重连间隔（毫秒） |

## 会话与工作区

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `provider` / `model` / `preset` | 空 | 指定模型与预设；`preset` 留空时新会话加载宿主默认预设，已有会话恢复原选择；设置页名称为“Agent 工具预设” |
| `cwd` | 空 | Agent 工作目录 |
| `workspaceRoot` | 空 | 每个 QQ 会话的独立工作目录放在哪；留空用 `<cwd>/会话` |
| `isolateByPeer` | `true` | 每个私聊 / 每个群各自一个工作目录 + 记忆区，互不可见 |
| `sessionIdleTimeout` | `1800000` | 会话闲置多久回收（毫秒） |

## 门口通信与共享记忆

- `doorDir`：来信目录，留空关闭；每封信是一个 Markdown 文件。
- `doorReplyPrefix`：回信文件前缀，默认 `回复-`。以前使用自定义命名的实例应显式设置为原前缀；此前缀的文件不计入未读。前缀不能含路径分隔符或以 `_` / `.` 开头。
- `doorSenderLabel`：来信来源显示名称，默认「其他会话」，仅为标签，不验证发件人身份。读取频率由对方决定。
- `memoryRoot`：显式配置后启用 `qq_memo`；新会话模板通过工具说明如何访问共享记忆，不注入宿主绝对路径。

新会话的随笔写在自身 `记忆区/随笔/` 内，不保证管理员不可见。已有用户 `AGENTS.md` 不覆盖、不自动追加；升级后请检查并移除旧模板遗留的个人路径及越界日记指令。

## 先判断是不是在和机器人说话

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `addressClassifierEnabled` | `false` | 群聊/私聊启用独立判断；群聊要求 @ 时，还须自身 @ 且判断放行，不能绕过访问控制、作息与限流 |
| `addressClassifierProvider` | 空 | 判断模型的 provider；留空使用插件明确配置的 `provider` |
| `addressClassifierModel` | 空 | 判断模型名；留空使用插件明确配置的 `model` |
| `addressClassifierReasoningEffort` | `low` | 可填写该模型支持的推理强度 |
| `addressClassifierTimeoutMs` | `30000` | 判断超时毫秒数；失败保留消息并记录错误 |

需要宿主提供 `llm` 服务，并明确填写 provider 和 model；此调用不自动继承宿主默认模型或主会话预设。先配置模型再开启开关，可在设置页修改。

判断为 `no` 不启动主模型，源消息和已处理的附件保留；后续 `yes` 会按顺序一起提供此前未交付的消息。判断提示、结论和推理不进入主聊天。关闭后，群聊待处理内容继续保留，按当前“必须 @”或定时合并规则交付；私聊未交付内容按顺序转入普通处理，新消息不能越过旧队列，不再发起分类请求。重启后同样恢复，访问控制、作息和忙碌限制仍有效。

分类器只读主 session 当前完整有效的聊天上下文和已记录的系统提示、工具说明，并带入尚未进入主 loop 的消息。DSH 压缩后使用当前摘要及保留内容，不自行截取最近条数。主会话的这些内容只作为背景，分类器不能执行其中的工具或任务，也不会更新主会话的人设注入等标记。

分类器通过宿主 `attachments` 服务接收实际图片，需配置支持图片输入的模型。主会话已有的图片、待处理消息的图片和本条消息的图片均按来源附带，不靠图片 URL 或路径猜测内容。每条新消息最多接收前 4 张，单图沿用 `imageMaxMB`，并遵守宿主附件大小与格式限制（PNG、JPEG、GIF、WebP）。图片下载、入库失败、附件服务缺失或模型明确不支持图片时，记录错误并保留消息，不悄悄改成纯文本判断。

“屏蔽成员图片”仅约束主会话的实时图片输入，分类器不受此限制；因此开启分类器后，被屏蔽的图片仍可能下载并交给分类模型。仅供分类的图片由宿主附件服务保存，待处理记录只保存引用，不把图片内容或可读路径补进主会话。重启后继续使用已保存引用；附件保存与清理由宿主负责，独立于原来的本地图片缓存。分类器未启用时，全图屏蔽仍不会下载该成员的实时图片。

返回格式先严格匹配 `yes/no`，再从正文正则提取完整单词；同时出现 `yes` 和 `no` 时不采用。仍无法识别就重试两次（合计最多三次请求），最后按 `yes` 放行，并在插件的每日日志中以 `warn` 记录 `fallback_yes`、会话、源消息 ID、模型与次数，不记录回答原文或推理。超时、网络或配置错误仍保留消息并报错，关闭和卸载不触发兜底。

睡眠或忙碌暂时阻止交付时，消息留在磁盘；重启可恢复已放行的消息。附件沿用原有图片缓存，尚未交付或仍在本轮处理的附件暂不清理，本轮结束后恢复普通缓存规则。待处理消息长期积压仍会占用磁盘。保存范围、异常处理和验证边界见[开发进度](emotion-system-development.md)。

## 群里怎么说话

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `requireMention` | `true` | 群聊须通过协议消息段 @ 自身才启动主模型；名字、引用、问句和分类结果不能绕过 |
| `groupMentionOverrides` | `{}` | 按群覆盖，例如 `{"70001": false, "70002": true}`；未列出的群沿用全局设置 |
| `groupMessageIntervalMs` | `30000` | 免 @ 且未开分类器时，从第一条消息起固定等待后合并处理；后续消息不延长，自身 @ 或触发词可提前结束等待 |
| `groupTriggerWords` | `[]` | 免 @ 且未开分类器时，当前消息文字包含任一词即立即处理；区分大小写，不使用正则，不匹配引用、转发内容、历史或 @他人的昵称 |
| `addressedMaySilent` | `false` | 群聊被自身 @ 时也允许沉默；不改变触发条件 |
| `groupMinGapMs` | `4000` | 群聊任意两条回复之间的最小间隔（毫秒），防风控 |
| `historyLimit` | `20` | 群聊带多少条最近消息当上下文 |
| `quoteReply` | `true` | 消息带引用时，把「被引用的人 + 原文」一起交给 Agent |

第一条待处理消息开始计时；没有新消息就不会运行。主模型忙时继续合并，空闲后串行处理；处理范围固定之后到来的消息留到下一轮。模型可以沉默，观察仍会消耗一次主模型请求。开启分类器时不再另设定时观察。

触发词可在设置页用逗号分隔填写，例如 `小助手,来看看`。默认空；命中只提前结束等待，不强制回复、不替代“必须 @”，也不绕过分类器。自身 @ 无需加入词表，首条消息就是自身 @ 时同样立即处理。

旧 `groupFree` 名单读取时迁成对应群的 `groupMentionOverrides: false`，已有明确逐群设置优先；下次保存设置时写成新字段。全局 `requireMention` 保留原值。旧 `groupWakeMs`、`groupWakeIdleMs`、`groupRepliesPerWindow`、`groupReplyGapMs`、`groupWakeNameMention`、`groupWakeQuestion`、`groupWakeKeywords`、`groupWakeProbability`、`groupWakeNames` 退役，读取时忽略，保存时移除；因此开启“必须 @”的群不再有保活或名字唤醒旁路。`groupMinGapMs` 和每分钟发送限流保留。现有 session 的固定 system 仍按既有锁定和同步规则更新。

## 发送前的敏感内容检查

`auditOutbound` 默认开启，在本地检查文字，不创建审核会话、不调用模型。正文、文字发送工具、语音合成前的文本及空间说说正文共用检查规则：匹配插件配置和当前连接使用的 NapCat `accessToken` 原值，以及少量明确的 API Key / GitHub Token 格式。插件不会为此读取宿主模型密钥或扫描环境变量。

路径、`file://` 链接、通用 `password: 示例` 和 `Bearer 示例` 不再默认拦截。需要额外限制时通过 `auditExtraPatterns` 配置正则，旧配置字段保持兼容；无效正则跳过。设置 `auditOutbound: false` 会关闭内置和自定义检查。

命中后阻止该段原文，尝试向当前聊天发送固定提示“这条回复包含疑似敏感信息，未发送。”；工具调用同时得到明确失败，不自动重试或额外请求模型改写。固定提示仍受静默轮、限流和网络状态限制，但不会被自定义规则再次拦截。私聊流式回复命中后停止该轮后续正文转发，下一轮恢复正常；已经发出的内容不能撤回。

检查日志只记录聊天、会话、消息关联信息、发送来源及规则标识，不记录命中的原文或自定义正则内容。聊天发送记录只记实际发出的内容；宿主原始模型历史和工具调用记录仍按宿主规则保存，本检查不会清理它们。

这是防误发检查，不是完整的秘密识别或文件审查：不识别所有凭据，不检查图片和文件内容；流式回复按待发送片段检查，不保证识别跨片段拆开的秘密。`/cwd` 等命令权限仍由命令入口控制，路径不再被发送出口统一禁止。

## 聊天命令

支持 `/new`、`/reset`（新建会话）、`/status`（会话状态）、`/cwd`（会话目录）、`/help`（帮助）；也支持 `#` 前缀。

私聊可直接发送命令。群聊必须在命令前使用 QQ 的 @ 功能选择机器人，例如 `@机器人 /status`；按消息段中的目标账号判断，手输 `@昵称` 不算。按群免 @、关闭 `requireMention` 或开启分类器，都不能代替群聊命令的显式 @。带其他 @、媒体或额外正文的消息不会作为命令执行，继续按普通聊天规则处理。

命令仍受聊天白名单和同类机器人开关限制，目前不额外要求发送者在 `ownerIds` 中。群聊 `/new`、`/reset` 会切换整个群共用的会话；私聊只影响当前私聊。

## 没人说话的时候（主动开口）

它是「来消息才动」的：没人说话，它就永远不出声。这一组配置给会话加一个冷场闹钟 —— 安静够久了，就往会话里投一句「可以主动开口了」。**说不说仍然由它自己决定**（不想说就 `[SILENT]`），这一层不替它说话。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `proactiveEnabled` | `true` | 冷场主动开口的总开关 |
| `proactiveSilentMs` | `1200000` | 安静多久算冷场（毫秒，默认 20 分钟）。**必须小于 `sessionIdleTimeout`**（默认 30 分钟），否则会话先被回收，就轮不到它开口了 |
| `proactiveMaxPerDay` | `6` | 每个会话每天最多主动说几次；`0` = 不主动 |
| `proactiveQuietHours` | `23:00-08:00` | 这个时段不主动开口；格式 `HH:MM-HH:MM`，留空 = 不限 |

除了这四项，还有两道内置的闸：两次主动之间至少隔 1.5 倍冷场时长；连着 3 次主动开口都没人接，这个会话今天就先闭嘴。

## 作息（睡前提醒 · 晚安静默 · 夜里的消息留到早上）

私人用的一套作息：到点提醒她去睡，她说「晚安」之后就不再回消息，休息时段收到的消息不立刻回、攒到早上一次交出去。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `sleepMode` | `true` | 作息总开关 |
| `bedtimeAt` | `23:30` | 到点提醒一句「该睡了」，每个会话每天一次；留空 = 不提醒 |
| `sleepFrom` | `00:00` | 休息时段从几点开始。这时候起收到的私聊**不立刻回**，只记下来 |
| `sleepTo` | `08:00` | 休息时段到几点结束。出窗口时把夜里攒的消息一次性交给它，附上「昨晚你发来这几条」 |
| `goodnightWords` | `晚安,睡了,睡觉,去睡,我先睡,困了,睡啦` | 说到这些词就当她说晚安了；之后不再回消息，直到第二天 `sleepTo`。逗号分隔 |

两个细节：**说晚安那条本身照常回**（得有人应一句），静默从下一条开始；**群聊不参与作息**（群里的消息照常处理，只是群聊默认是关的）。

## 夜里的读书问询（默认关，只有本地开）

半夜没人说话，但也不是完全没事可做。这一层会在夜里挑一两次，往会话里投一轮**问询**——问它要不要看会儿书。**它可以拒绝**，拒绝了就什么都不做，不用回话、不用解释。

这一轮里它说的话、调的发送工具**一律不会发出去**：`send()` 里和几个发送工具里都硬拦了一道（`record.quietRound`）。所以就算它半夜突然想说点什么，对方手机也不会响。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `readingEnabled` | `false` | 总开关。默认关——发布版的人看不见这一层 |
| `readingHours` | `01:00-05:00` | 只在这段时间里问，格式 `HH:MM-HH:MM` |
| `readingAskCount` | `2` | 一夜最多问几次（拒绝也算问过）；`0` = 不问 |
| `readingAskGapMs` | `10800000` | 两次问询至少隔多久（默认 3 小时） |
| `readingBook` | （空） | 书名；留空 = 这层不启用 |
| `readingChapterDir` | （空） | 章节目录，用来判断**读完没有** |
| `readingBookmark` | （空） | 书签文件，从「下次从哪接」那列接着读 |
| `readingPeer` | （空） | 问询投给哪个 QQ 号；留空 = 私聊白名单第一个 |
| `readingTimeoutMs` | `1200000` | 一轮最多等多久（默认 20 分钟——真读两章再写书签，比闲聊慢得多） |

**读完了就不再问**：书签上「下次从哪接」的章号超过 `readingChapterDir` 里最大的章号，这一夜就不再问——问了也只能得到一句「没得看了」。

书签是五列的 markdown 表（四列的旧书签认不出来，会当「还没开始读」处理）：

    | 书 | 读到哪 | 哪天 | 下次从哪接 | 一句话心得 |

    | 网游之天下第一 | 第2章 | 2026-10-27 | 第0003章 | 柳云死得干脆 |

## 上下文 · 人设 · 记忆

当前事项与长期记忆统一保存在插件家目录的 `memory/<聊天标识哈希>/memory.json`，使用 `qq_memory` 查询、更新及查看历史。每轮结束后独立调用模型自动维护事项；维护失败保留待处理消息，状态区标为尚未核实。旧便签、交接、话头、事实卡和群词典只做一次迁移，随后停止自动读写和注入；旧未完成内容先标为待核实，不直接恢复。详见[记忆整理方案](memory-design.md)。

有效事项、当前聊天的有效事实及群词、授权群近况和表情包资料在每次请求的全部输入末尾提供一份最新资料，响应后移出后续模型历史，不参与 compact；原快照与清理操作保存在宿主日志。接受从上一轮状态位置起的尾部缓存失效；完成记录与旧版本按需查询。情绪、好感及场景计算尚未接入。群近况只向明确的 owner 提供，并只读取 `groupAllow` 明确列出的群；关闭群聊后立即停止提供。

固定人设和聊天规则放在 system，默认只在新建会话或成功压缩后同步；普通请求、工具续调和重启恢复均沿用会话已保存的快照。修改相关设置后，页面列出受影响的会话，提供「创建新会话」「压缩会话」「强制同步」「稍后同步」。创建新会话会切换上下文；压缩保留摘要；强制同步保留当前会话和完整历史，直接更新 system，可能降低后续请求的提示缓存命中率、增加费用和延迟；稍后同步则等下一次新建或成功压缩。同步后 system 重新锁定。操作等待当前回复结束，失败显示原因。设置页与 QQ 进程分离时，由 QQ 进程执行，离线时保持排队。

状态区使用 DSH **0.2.2-rc.2** 的官方快照和消息替换接口，响应提交后清理旧状态，无需宿主补丁，见[接入说明](host-transient-context.md)。升级已有会话保留原 system，通过现有新建、压缩或强制同步选项更新记忆使用规则。安装要求 `>=0.2.2-rc.2`，当前已验证版本为 `0.2.2-rc.2`；其他版本默认暂停 QQ，可在全局风险弹窗中明确确认后启用，设置页可重新打开弹窗。许可绑定六个核心包的具体版本，变化后需重新确认。无界面部署使用 `acceptedDshVersions`，详见接入说明；手动压缩需启用宿主压缩服务，不能与同一作用域内另一个 `complete: true` section 并用。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `contextGuard` | `true` | 只记录上下文用量与压缩情况，不注入状态卡、不主动切换 session |
| `memoryProvider` | 空 | 记忆维护 provider，留空沿用插件明确路由或当前主会话路由 |
| `memoryModel` | 空 | 记忆维护模型，留空沿用插件明确模型或当前主会话模型 |

## `chatLog` 为什么值得开着

流水保存详细原文，便于核对具体措辞和消息时间；它由插件记录，不依赖模型写日记，也不另花维护调用。被跳过的群消息也会记录。自动记忆只整理事项和必要事实，不能代替完整聊天档案。

要注意这是**原始流水，不是日记**。要日记还得让 Agent 自己（或者定时任务）从流水里提炼，见 [让它自己长期跑](deployment.md)。写失败只记调试日志，绝不影响聊天。


### 按群触发与图片过滤

- `groupMentionOverrides`：统一覆盖该群是否必须 @，仍受群访问控制、同类机器人开关和作息限制。设置页可逐群选择或恢复全局默认。
- `groupImageBlock`：按群成员过滤主会话的实时普通图片；分类器和 `qq_images` 历史取图不受此限制。`"群号:QQ号"` 屏蔽全部图片（未开启分类器时不下载）；`"群号:QQ号:宽x高"` 只屏蔽精确匹配的尺寸（单位像素，宽高顺序不同视为不同尺寸）。例如 `["123456789:10001:1920x1080", "123456789:10001:1080x1920", "123456789:10002"]`。同一成员可配置多个尺寸，全部屏蔽规则优先。尺寸过滤需获取图片字节进行检查，命中后不写入图片缓存；尺寸无法解析时不提供该图。只保留文字和 `[图片]` 占位符，不向主模型提供尺寸或过滤原因。纯图消息仍按正常触发规则处理。商城表情（`mface`）不属于普通图片。已有缓存和已经进入模型上下文的图片不会追溯清除。

以上字段可在设置页或 `settings.json` 修改，无需重启。

### 群聊与私聊作息

`groupSleepFrom` / `groupSleepTo` 与 `privateSleepFrom` / `privateSleepTo` 分别设置休息时段，格式为 HH:MM；留空沿用 `sleepFrom` / `sleepTo`。
只有 `sleepMode` 和 `holdNightMessages` 均开启时才静默。群消息不投递也不排队；私聊消息在私聊休息结束后统一交付。默认 `holdNightMessages=false`，照常回应。

### 语音、私聊流水与空间工具

- `qq_send_voice`：Windows SAPI 合成语音，最多 500 字。`voiceName` 留空使用系统默认声音，指定名称不存在时明确报错。音频直接传给 OneBot，协议端不需要访问宿主的临时文件。
- `qq_private_history`：仅私聊可用。`ownerIds` 中的主人能查询正文；其他人需要插件家目录 `affinity.json` 中的好感度达到 100（或字符串 MAX），仅返回日期时间。查询其他人的记录仅限主人。默认查一天、40 条，最多七天、200 条。
- `qq_qzone_send`：仅主人私聊可用。展示文案、图片与可见范围并得到确认后再调用；默认公开，可指定 friends 或 private。每天最多两次发布尝试，额度保存在插件家目录 `qzone-state.json`。超时、失败不会删图重发，也不会释放本次额度；请先检查空间是否实际发布。

QQ 设置页“记忆区与工作区”中的“Agent 工具预设”对应 `preset`，填写宿主已有的预设 ID，不是模型名称。留空时，新会话也会挂载宿主默认预设，并记录实际选择；恢复时优先使用会话已经保存的预设。修改此项只影响后续新会话，已有会话保持原预设；需要立即使用新选择时可通过 `/new` 新建会话，原历史不带入。

复用宿主内已经运行的 QQ Agent 时，保留已挂载的预设及其版本；缺少挂载时等当前轮结束再补齐，不重复注册工具。挂载失败或已记录的预设不存在时明确报错，不静默换成其他预设。宿主完全没有预设服务且未指定 `preset` 时仍可使用全局工具组合；显式指定或恢复已记录预设的会话则需要预设服务。`read_image` 来自宿主工具组合，所选预设需要包含它，QQ 插件不会另造一个同名工具。
