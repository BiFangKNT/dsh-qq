# 参考资料

参考资料用于查询用户提供的说明、词义、角色设定等原文片段。它不是聊天记忆，也不是聊天记录：当前事项和长期事实由 `qq_memory` 管理，聊天原话用 `qq_history` 查询。

## 添加与使用

进入设置 → QQ → 参考资料，填写机器人 QQ 号、资料名称、访问范围、可访问聊天以及来源。来源支持：

- **文本文件**：运行 QQ 的机器上的 UTF-8 `.md` / `.txt`，填写绝对路径。
- **文本目录**：只检索明确选中的目录内的 `.md` / `.txt`；不自动扫描整个聊天工作目录。隐藏目录、隐藏文件、`node_modules` 不读取，链接和目录联接不跟随。
- **可选角色资料包**：现有 AI 拟人同人角色的名称、别称、外貌和来源。默认未启用，不决定机器人人设。
- **旧梗词库导入**：仅供迁移已有 `memes` 表结构的 SQLite 词库。新用户使用文本文件或目录，不需要制作数据库。此入口按只读来源处理，不修改原库；旧库更新后同样在查询时重新读取。

路径是**运行端路径**，不是打开网页的电脑路径。本版不上传文件、不导入网页、PDF、Word 或压缩包。远程部署需先将文本放到运行端，再填写路径。

点击“添加资料来源”时检查格式、容量、读取权限。编辑可以更换来源、范围和目标聊天；移除仅删除登记入口，不删除原文件。文件内容直接在原位置维护，不另存一份可编辑原文。

模型通过同一个 `qq_search` 搜索和读取原文：

- **搜索**：默认 `action: "search"`，按标题、别名、关键词查找，最多返回 5 处命中。结果包含命中附近的原文预览、来源 ID、资料名、相对文件名、行号，以及段落和章节的位置。预览通常最多 1200 字符，`partial: true` 明确表示只展示局部。
- **读取**：`action: "read"`，使用搜索返回的来源、文档 ID 和版本，可以读取完整段落、章节或全文。内容过大时先返回连续的一部分；`nextOffset` 非空表示还有后文，可以从这个位置继续读，直到返回 `null`。

正文不限制单行长度，不插入换行、不删空白、不改写长 URL 或 JSON。每次完整结果按 JSON 字符串长度最多 16000 字符，包含元数据、转义和错误提示。搜索结果过多或预览不完整时标记 `truncated: true`；读取结果用 `partial` 和 `nextOffset` 表示是否还有后文，不把局部伪装成全文。

索引中用于显示的名称最多 512 字符、标题 160 字符，别名与关键词最多取 1000 字符参与匹配；超长元数据截短不影响通过文档 ID 读取原文。没有命中就明确返回没有命中。中文按字和相邻双字检索，英文按词检索，中英文连写仍保留完整英文词，标题和别名优先；它不是语义搜索，不保证理解同义表达。在文本开头写 `别名：…` 或 `关键词：…` 可以帮助匹配。

只有当前聊天配置了可见来源时才提供 `qq_search`。获准聊天可查询自己可见的资料；不能通过参数指定其他聊天。QQ 侧用 `qq_sources` 管理来源，仅授权账号私聊可用，管理时须明确选择目标聊天或公共范围。设置页是运行端管理入口，具备与其他本机设置相同的管理权限；纯设置进程与运行端使用同一插件数据目录时共用登记。

## 私有与公共范围

私有资料绑定“机器人账号 + 私聊或群聊 + 对方或群号”。例如机器人 `90001` 的 `group:70001` 与 `private:70001` 是两个范围；另一机器人不能检索这份资料。多个聊天即使共用 cwd，也不会自动共享资料。

公共资料仍属于一个机器人，必须列出允许查询的聊天，例如 `group:70001, private:10001`。未列出的聊天不能查，留空时任何聊天都不可查。不会自动开放给所有群、普通 Agent 或整个 DSH。

资料导入不授予新的聊天访问权；原白名单与关闭设置继续生效。管理工具的授权身份在执行及异步读取完成后复查，查询期间撤销来源或修改范围后不返回已撤销内容。公共资料对聊天模型只读；检索不会写入资料，也不把聊天记忆自动写到公共库。

## 更新、容量与上下文

不使用向量模型或额外检索服务，搜索和读取本身不调用额外模型。来源登记保存在插件数据目录的 `knowledge/knowledge.sqlite`；检索索引在内存中按原文指纹建立和更新，可随时重建。最多缓存两个来源的索引，重启后按需重建。

每次实际查询重新检查并读取可见原文，内容不变时复用关键词索引。修改、增加或删除文件后，下次查询生效；读取失败、链接或格式发生变化时不使用旧片段，返回来源不可用提示，详细原因写运行端日志。来源与索引独立于 session，`/new`、compact 或重启不清空来源登记。磁盘内容变化不会自行发起模型请求。

Markdown 使用语法解析器定位标题、段落、代码块、表格、列表等结构；代码中的 `#` 不会当成章节标题。章节到下一个同级或更高层标题为止，包含子章节。纯文本按空行分段。索引只记录位置，正文始终取自原文；原始 CRLF、BOM 和空白保留，超长单行或代码块可分次读取，续读不会插入新换行。

读取必须使用搜索返回的原文版本。搜索后、读取前文件发生变化时，旧位置会被拒绝，仅返回简短的工具错误 `STALE_REFERENCE`，不返回正文。工具说明要求：本次未读取成功，不能据此声称已读到最新原文，须重新搜索后再读取。这个错误不会改写此前成功返回的内容，也不代表旧版本的所有内容都已错误；新的搜索会读取当前文件。不在每次失败结果里重复处理说明。读取与搜索一样检查当前聊天权限，异步读取期间撤销来源或变更授权也不会返回旧内容。

工具调用示例：先调用 `qq_search {"query":"连接配置"}`。从命中结果取 `sourceId`、`documentId`、`version`，再调用同一个工具的 `read`：不填位置读全文，填 `block.offset/endOffset` 读该段，填 `section.offset/endOffset` 读该章节。返回的 `offset/endOffset` 是本次实际读取的范围；若 `nextOffset` 非空，下次用它作为 `offset`，沿用 `rangeEnd` 作为 `endOffset`。位置从 0 开始，按 UTF-16 计数，终点不包含在范围内；模型直接沿用返回值，无需自行计算。

容量限制：单个文本文件 512 KiB，每个来源最多 128 个文本文件、8 MiB 文本、10000 个结构块；目录最多 12 层、2048 个目录项目；最多登记 64 个来源。一轮搜索最多处理 32 MiB、20000 个结构块，超过限制的来源明确标为本次未使用。旧 SQLite 文件最多 256 MiB、10000 条记录，展开后的文本仍受 8 MiB 和结构块数限制。读取是异步的，语法解析和关键词建索引在本进程完成，因此大目录首次查询会比小文件慢；需要时拆成更具体的来源。

原文和检索片段不放进固定 system，也不放每轮末尾状态区。只有调用检索工具后的结果进入正常工具历史，后续按宿主正常历史和压缩规则处理；它与“每轮被替换的状态”不同。提供或收回工具本身可能影响工具列表缓存，不承诺完全没有缓存变化。

## 从旧功能升级

- `qq_memo`、`qq_meme` 已移除，不保留重复调用入口。升级前已生成但尚未执行的旧工具调用会失败，不自动重放整轮。
- `memoryRoot`、`memeDb`、`DSH_QQ_MEME_DB` 只用于显示迁移线索，不再启用旧工具。旧共享目录原文件保留；管理员选择具体文件或目录，决定归入某个聊天还是公共资料，不自动索引、自动公开。
- 旧 `aiGirls` 不再将角色图鉴放进新生成的 system，也不自动开启资料包。需要时显式添加角色包并选择范围。
- 已锁定的 system 不会直接改写。已有会话里的角色图鉴与旧工具说明，通过原有的新建会话、compact 或设置页的同步操作更新。强制同步仍由用户明确选择。
- 不修改宿主源码、预设、普通 Agent 工具或现有记忆维护流程。Workspace 的原文件权限不由检索功能扩大；资料可见范围是检索工具的边界，不能冒充对宿主所有本机文件工具的沙箱。
