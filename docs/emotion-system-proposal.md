## 1. 已确认的方向

系统维护机器人的短期情绪、各类需求和按人的长期关系，经历与时间共同驱动变化，状态影响表达，并可查询、解释和恢复。

- 完整六欲、睡眠、心愿、求助等都是合理且可实现的功能，保留在需求范围内。实现先后由开发安排，不以复杂或尚未接入作为删除理由。
- 情绪为同一机器人身份的全局状态；对不同人的关系独立记录。只跨会话共享脱敏状态，不共享其他会话的原因正文、人物身份和交互时间。
- 好感与权限分开，分数上涨不能授予历史查询、管理员或工具权限。
- 增加用户提出的可选前置分类器：独立 session 判断新消息是否在对机器人说话，默认推理强度 `low`，支持自定义。额外延迟和成本不是阻塞项。
- 无互动情绪变化、等待回应的冷落、长期断联好感衰减需要区分定义，作为可选机制；先整理参数，不擅自删除或补造数值。
- 真实收到的消息保留，按作息和会话规则处理。错过的主动开口机会不累积补发，恢复运行或醒来后重新判断当前意图。
- 最终测试验证客观逻辑漏洞；角色是否自然、亲疏是否合适由用户自测反馈，不作为自动验收标准。

上一版关于“只保留社交需求”“删除断联衰减、复合欲和满值事件”“只联系一人”“取消复杂睡眠”等范围收缩建议撤回。是否改变具体业务规则，应说明逻辑冲突及修正方案，不能用实现复杂度代替需求决定。

## 2. 核心概念与边界

| 概念 | 含义 | 边界 |
| --- | --- | --- |
| 情绪 | 喜、怒、哀、惧、爱、恶六个独立存量 | 短期状态，不等于对某个人的长期关系 |
| 需求 | 食欲、睡欲、触欲、声欲、色欲、求知欲六个存量 | 以缺口存储；满足使缺口下降，不把方向写反 |
| 派生“欲” | 从喜、爱、色欲计算的展示指标 | 不独立演化；权重和色欲取值方向待定义 |
| 关系 | 按平台联系人身份记录的好感 | 与管理员、称谓和权限分离；不按群或昵称建人 |
| 原始消息 | 平台实际收到的消息及可信来源信息 | 分类 `no` 不删除消息，不伪造已被主模型消费 |
| 分类结果 | 是否启动本次主对话 loop | 不直接修改情绪和关系，不混入主模型 context |
| 事件 | 归一化的经历：来源、行为人、指向对象、类型和强度 | 人物归因来自可信元数据，内容事件可没有联系人 |
| 主动机会 | 此刻是否可以自主发起对话 | 不是收到的消息，不在睡眠/停机后逐条补发 |

各指标 0–100 是角色模拟量，不是总和 100% 的占比。六欲可展示满足度 `100 - 缺口`，但必须明确标签与方向，计算和展示不能混用。

“状态驱动表达”指由程序维护连续状态，再把表达要求交给生成层；不靠模型临时编造情绪数值。LLM 的语言实现具有不确定性，后续优化，不把主观语言效果当作数值引擎的通过条件。

会话回收、session 重建和 `/reset` 不自动清空角色状态。机器人身份、会话身份、联系人身份分开建键；显式状态清除才重置业务数据。

## 3. 前置分类器：独立且可选

### 3.1 明确的行为

启用范围内，每条新的合格入站消息先保留，再判断当前发言人是否正在对机器人说话：

1. `yes`：允许进入主对话 loop，向主模型提供正常上下文及此前未交付的源消息。
2. `no`：结束本次主对话处理，不启动主模型；源消息继续保留。
3. 返回无法识别：先从回答正文正则提取完整的 `yes` 或 `no`；两者同时出现时不采用。仍无法识别则额外请求两次，合计三次都无法识别时按 `yes` 放行，并明确记录 `fallback_yes` 日志。这是用户指定的兜底，不记作模型判断成功。
4. 请求失败：网络、超时、配置错误与 `no` 区分，记录明确错误，源消息保留；关闭或卸载不触发兜底，不用关键词或另一个模型猜结论。

示例：A、B、C 三条消息分别判为 `no`、`no`、`yes`；满足必须 @等交付条件且容量足够时，主模型应能看到 A、B、C 的完整原始消息，而不是只有 C，也不包含分类器的推理与判定过程。容量不足时按新方案明确截断范围或生成摘要，不宣称完整提供了原文。

前置分类器只解决“是否对我说话”。情绪事件识别解决“发生了什么、影响谁”，两者是不同职责；不再把前置分类器说成额外的情绪分类请求。是否复用一次结构化分析输出可在实现时决定，但职责和数据边界不变。

### 3.2 上下文与并发

- 分类器使用独立 session，不把分类提示、分类对话、结果或推理放入主模型 context。原始消息本身可以正常进入主模型，不属于污染。
- 分类器需要读取判断指代和接话所需的同会话上下文；独立 session 不等于只能无上下文看单句。
- 分类 session 按群/私聊隔离，不能因为独立于主模型就把不同人的私聊混在一个上下文中。
- 每条新消息只提交一次分类；旧背景消息可以作为判断上下文，不重复作为新的分类任务或刺激计分。
- 分类器 `no` 的消息不是“已消费”。目标方案分别保存进入主 session、模型处理完成和实际发送的进度；模型正常结束（含沉默）后推进处理位置，失败恢复不得盲目重新追加已接纳消息。默认左截断跳过的范围另记为未提供，不冒充已读。
- 异步分类使用消息序号与批次上界；分类期间新到的消息继续保留，不能被旧结果清空。
- 不把私聊连发合并当作“逐新消息分类”的替代。主模型回复轮次仍可合并，但不能丢掉单消息判定与来源。
- 需要定义历史保留和上下文容量上限。超限处理应显式设计，不能静默截断后宣称已交付完整上下文。

### 3.3 与现有触发规则的关系

账户/群/私聊访问控制、重复事件去重、审批问答等控制消息分流仍优先。分类器不扩大可接入对象，不拦截必须由既有控制通道消费的回答。

目标方案中，分类器负责语义上的“是不是在对我说话”，但“必须 @”仍是启动普通群聊主模型的硬限制。合格消息仍可逐条分类和保存为背景，不能凭名字、引用、保活或分类结论绕过必须 @。群聊命令另走结构化自身 @ 的既有入口。

分类器默认关闭，不依赖分类 session 才能正常聊天。目标方案中，关闭分类器且要求 @ 时只由自身 @ 触发；不要求 @ 时合并普通新消息后交给主模型，允许沉默。具体行为与配置迁移见[消息调整方案](group-message-design.md)，推理强度默认 `low` 不变。

分类器放行不等于立即外发：作息暂存、限流、阅读安静轮和出站审计仍然生效。

## 4. 完整业务需求

### 4.1 情绪状态与事件

保留六情的独立静息点、半衰期、事件影响、重复刺激持续时间与变化上限。默认参数使用原文初值，不擅自统一静息点或简化为只看单个正负分数。

事件覆盖原文的刺激、满足和内容摄入渠道。人物指向需要区分：有人冒犯机器人、有人攻击在意的人、有人讨论第三人经历，不能仅按负面关键词归因。来源内容、行为人、受影响对象分别表示，内容摄入允许没有联系人，不给他人加好感。

原文的情绪对偶压制、弱联动、六欲对增益的调制继续保留为行为规则；系数和计算顺序需补齐。只做一级联动，防止递归反应。不能因认为不符合真人心理规律而直接删除。

事件处理固定为时间推进、确认来源、计算调制、处理一级联动、应用额度、提交结果。每一步保留请求变化和实际变化；单次、窗口和满足限额之间的优先级必须写清。

被分类器跳过的消息后续进入主模型上下文时，仍保留自身来源和人物指向；背景消息不自动等于一次直接互动，也不得因重新进入上下文被反复计分。

### 4.2 六欲、满足和自我满足

保留六欲的缺口增长、有效满足渠道、满足后冷却、达到阈值持续一段时间后求助，以及内容消费带来的自我满足。

每个指标必须定义：增长时间段、增长函数、满足事件、单次满足量、冷却、限频、求助进入与退出条件。可以按配置启用指标；渠道未接入时明确标注未接入，不假造已经观看、吃过、听过或完成亲密交流的事实。

图片、语音、音乐、阅读等事件以实际可获取的数据为依据；已有图片屏蔽策略继续生效，不为情绪分析重新下载被拦内容。问“要不要看书”不等于完成阅读；模型声称已经做过也不自动成为可信消费回执。

保留派生“欲”的当前值、曲线和图例，计算不独立存档；具体合成参数见参数清单。

### 4.3 好感与按人账目

保留原文的按日结算、交流质量、解决需求、解决满值事件、好感对情绪冲击的调制，以及好感自身的变化速度规则。负向计分与完整公式尚不齐全，不能当作已有确定实现。

只依据该联系人造成的事件与贡献记账；不读取全局当前怒气给所有人扣分。需要保留制造者与帮助者，防止同一个人制造事件再重复领取解决奖励。特殊关系的加减分豁免来自独立关系配置，不来自管理员权限。

页面区分已结算好感与今日预计变化，日界线使用统一配置时区。已结算日期不能重复结算；规则配置变更不追溯重写历史分数。

断联衰减作为可选功能保留，不与正常互动日结捆绑开关。具体 5 天封顶、40 下限、10 天冷却及缺项见参数清单。

### 4.4 冷落与无互动：三个可选规则

| 规则 | 作用范围 | 原文目标 |
| --- | --- | --- |
| 无互动情绪漂移 | 全局状态 | 长期没有互动时哀、怒静息点缓慢上抬，有互动后回落 |
| 等待回应 | 一次明确等待 | 已向特定对象发出消息，超过等待阈值后产生一次哀伤影响 |
| 断联衰减 | 按联系人、按日 | 长期无交流使关系回落，受封顶、下限、特殊关系和冷却约束 |

三个规则分别记录时间和来源，允许关闭；不拿现有 `groupWakeIdleMs` 或 `proactiveSilentMs` 代替它们。关闭不能残留定时扣分，也不能在重新开启时补算关闭期间的惩罚。

发送成功才建立等待，通道失败不是被冷落。求助流程中的“未被回应者不因此扣分”必须在所有间接计分链路中成立；独立的自然断联衰减需要有自己的开启条件与来源。

睡眠、停机、重复发言、多会话回复、三类规则叠加和日结顺序都应补定义。参数未明确前不擅自选曲线，更不据此否定功能。

### 4.5 作息与睡眠

保留就寝提醒、话题结束或沉默后浅睡、高睡欲优先入睡、浅睡唤醒、再次入睡、深睡、睡足或到点起床、晚睡顺延、午睡和陪伴至指定时刻等功能。

扩展现有 `sleep.js` 为统一作息控制者，避免新旧系统同时决定能否回复。旧功能配置与新状态机需要明确迁移和优先级；不能在未启用新策略时改变现有默认夜间回应行为。

原文“睡眠中不计算”需要修正技术含义：睡眠中可以暂停普通情绪刺激和主对话推理，但接收、保存、起床计时和必要状态转移必须继续运行，否则无法可靠排队和醒来。睡欲爬满、深睡恢复及唤醒计数也需要统一时钟定义。

真实收到的夜间消息保留；醒来后按话题处理，过多时可摘要。它们与错过的主动机会分开：醒来后不补发一串此前计划主动说的话。

### 4.6 主动、求助、心愿和不满记录

保留四种不同业务，不压成单一“闲聊机会”：

- 阈值求助：特殊关系优先，再按好感联系高好感对象；按人等待、全流程超时、跨日中止、必要道别和解决后有限转告。
- 自愿主动：不依赖阈值，按对象日限次；长时间无回应暂停，待对方先开口后恢复。
- 每日心愿：由内容、前日对话、固定池产生，在对话中引出；数量、完成条件和换人条件需统一正文与原始需求口径。
- 不满记录：流程中止后记录结构化概要，限制保存与主动提起次数，不保存或跨会话复述他人原话。

所有主动意图复用现有调度和外发边界，不能各自起发送器抢额度。正在求助时的普通主动、多个指标同时求助、心愿与求助同时命中，需要明确合并/优先级；这是实现规则，不是删掉逐人求助的理由。

待发送意图必须有过期和幂等标识。睡眠、停机错过的机会不累积；恢复后按当前状态重新判断。真实收到的回应不能当作过期主动意图丢掉。

### 4.7 满值事件与表达

保留负面高位求助、满值特殊事件和亲密需求满值状态。锁定应解释为普通变化被冻结，不是禁止接收修复事件：安慰、道歉、示好或到期解除必须仍可检查和执行，否则锁无法解除。

负面解除后减半、亲密状态持续交流解决或超时减半并带动哀怒等规则保留；强制状态转移与普通变化额度之间的关系需要明确定义，不能让 15 点限额把“减半”悄悄改成另一种结果。

表达由关系基调、主导情绪、需求与当前场景共同生成。保留滞回、短答/句数/称谓等具体输出差异、低好感礼貌疏远、重新联系的生疏感与高好感豁免。各指标候选幅度应归一到明确口径，不直接把静息偏离和缺口大小混比而不定义。

程序只生成风格要求，不授予权限、不把其他人的私事放入当前生成上下文。语言表现的自然程度后续由用户反馈优化。

### 4.8 可视化、查询和记忆

保留十三指标分组、曲线、阈值提示、好感与日变化、未互动联系人标记和本地查询。闪烁与高亮规则属于可实现的界面行为，不因审美判断直接删除。若展示占比，必须明确分母，不把相互独立的强度误标为份额。

趋势可切换原文要求的日内区间与周区间，桶末值和峰值分开。缺失历史不补造；抽样和聚合属于可调整实现，需保留需求要求的信息，不固定照搬存储结构。

对话查询受可信身份与原文隐私分级约束，公开群聊不暴露其他会话的身份、原话、时间线和关系明细。好感达标只影响允许描述的关系/心情内容，不增加管理或历史访问权限。

保留情绪影响长期记忆重要度的需求，仅调整权重，不改正文和条数。宿主接口未核实属于接入工作，不能假设已经有接口，也不直接删掉需求。

## 5. 需要修正的客观冲突

| 原文问题 | 必须明确的处理 |
| --- | --- |
| 全部惰性结算，又要求无人时主动、日结和醒来 | 用同一时间差计算函数，由消息和低频时钟共同触发 |
| 每条事件都必须绑定人，又允许无对象内容摄入 | 来源、行为人、受影响对象分开；内容事件允许联系人为空 |
| 睡眠全程不计算，又要求深化、排队和起床 | 保留接收、持久化和状态机计时；暂停的是指定业务处理 |
| 重启不丢已生效状态，又 30 分钟才落盘 | 关键状态、日账、去重和流程标记提交后再发布生效；周期采样另算 |
| 单次 15、窗口 20、满足 25、解除减半 | 定义各自适用范围、累计口径和优先级，不靠执行顺序偶然决定 |
| 等待事件只计一次，却随等待变强 | 定义事件生效时刻和强度取样方式，避免 tick 频率改变结果 |
| 五天连续衰减与十天冷却 | 定义冷却开始点、重置点和周期关系，否则无法唯一计算 |
| 夜间每次唤醒加快入睡，又说唤醒计数重置 | 区分整夜唤醒次数与连续消息唤醒计数，分别定义重置点 |
| 睡眠期间不发主动消息，醒来“补发” | 按用户确认取消错过机会的逐条补发；真实收到的消息仍处理 |
| 全局心情、按会话记忆隔离和隐私分级 | 全局共享脱敏数值/风格，原因仍按来源权限访问 |
| 单条处理 200ms 与新增模型请求 | 区分本地计算与模型等待；分类器成本和延迟不是阻塞项 |

参数清单明确标出了原文已有值、缺项和当前源码字段。数值是角色设计参数，原文可作为初值，不要求心理学实证；测试检查单位、函数、边界和规则组合是否自洽。

## 6. 实现架构：单进程内的模块

不遵循原文十层结构，不拆微服务，不建设规则 DSL。建议在插件内增加 `src/emotion/`，初期四个职责文件即可：

| 模块 | 职责 |
| --- | --- |
| `engine.js` | 纯数值计算、时间演化、额度、按人账目和状态转移；输入同样则结果一致 |
| `perception.js` | 前置对话指向分类与情绪事件提取的适配；两个职责分别有输入输出契约，不持有最终分数 |
| `service.js` | 全局串行提交、时钟、去重、生命周期、流程协调、查询快照 |
| `store.js` | 带版本的持久化、恢复、保留期与一次性迁移 |

求助和心愿等规则先用明确的状态与普通函数实现，规模需要时再拆文件，不预建通用工作流框架。新增需求指标扩展定义、满足事件和行为策略，不复制引擎。

### 6.1 消息流程

```text
入站去重、可信身份、访问控制、控制消息分流
  → 保存原始消息与顺序
  → 可选前置分类器（独立 session，逐新消息判断）
      no：保留消息，退出本次主 loop
      yes：读取尚未交付消息及正常上下文
  → 作息/排队规则下接纳主轮次，保留单消息来源与交付游标
  → 情绪事件输入 → 时间与状态更新 → 持久化 → 当轮风格快照
  → 现有 Agent 轮次与统一外发

低频 tick → 同一状态提交路径 → 日结、睡眠/求助转移、采样、主动候选
设置页面 → 读取运行端快照，不另算一份业务状态
```

情绪提取的模型接入和当轮生效时点需核实宿主支持，不预设还必须新增第二个独立分类 session。前置分类器的分类内容不注入主模型以解释“为什么放行”。

现有按会话 `enqueue` 不能防止跨群同时改全局情绪，因此业务提交另用一个串行队列；模型调用和完整回复不占住数值写队列。异步结果带事件身份、时间和版本，晚到结果不得重复入账或覆盖新状态。

### 6.2 时间与持久化

时间演化按实际时间差及业务边界分段，不按 tick 次数累加。使用有效处理时间和顺序号，时钟回拨不得造成负时长或二次日结。停机补算策略按业务分别定义，不能把六小时补算上限直接用来跳过睡眠起床或若干日账。

单一运行端持有状态写入资格，`uiOnly` 只读。会话交付游标、情绪与关系账目、额度、等待/睡眠/求助状态一同保存，避免重启后只恢复数值却再次扣分或重复联系。

首选带版本的本地 JSON 快照和独立的保留消息数据，串行提交、同目录临时写入及替换；文件布局由 `store.js` 封装。消息归档与状态跨文件时，以稳定消息键和可恢复游标处理幂等，不声称两个普通文件天然具有跨文件事务。

写入失败和数据损坏显式报告，不静默清零、不推测旧数据、不自动换一套业务规则。已提交状态的进程退出恢复、真实文件系统上的替换行为在最终故障测试中验证。不为扩展性同时实现多种存储后端。

| [`src/session.js`](../src/session.js) | 主模型 session 与分类 session 分开；按会话队列与全局业务写入队列分工 |
| [`src/prompts.js`](../src/prompts.js) | 动态风格每轮渲染，不能只放首次 `buildChatPrompt` 注入 |
| [`src/wake.js`](../src/wake.js) | 自愿主动、求助、心愿共享调度与发送限制，区分业务状态 |
| [`src/sleep.js`](../src/sleep.js) | 统一扩展睡眠状态机，定义旧配置兼容，避免两套作息同时拦消息 |
| [`src/reading.js`](../src/reading.js) | 保留 `quietRound` 硬限制；真实阅读完成与问询事件分开 |
| [`src/settings.js`](../src/settings.js)、[`client.js`](../client.js) | 参数开关、状态查询和展示；分离 UI 进程读取运行端状态 |
| [`src/config.js`](../src/config.js)、[`cordis.patch.yml`](../cordis.patch.yml) | 新增参数同步；未定义值不能伪装成用户已确认默认值 |
| [`src/private-history.js`](../src/private-history.js) | 解除好感与历史查询权限的耦合，保留明确授权边界 |

当前 `inbound.js` 的群消息 backlog 仅保留 30 条并在取出时清空，不能原样复用后宣称满足分类 `no` 消息完整保留和失败可重投。已有聊天流水也不能直接等同于带交付游标的可靠消息存储。

当前 `private-history.js` 读取 `affinity.json`，非主人好感数值达到 100 或为 `MAX` 时有部分时间线查询资格。接入动态关系前核实实际文件和外部维护者，将授权与关系分别迁移；`MAX` 不自动成为管理员。不得覆盖尚未核实的外部数据或长期维持两个关系写入者。

新增本地状态查询不直接继承任意来源可读的 CORS 策略。跨进程页面读取真实运行端；运行端离线时显示离线，不在页面进程模拟另一份状态。

## 8. 实施顺序与最后的验证

开发安排可以分步完成，但完整业务需求不因此消失。先核实模型调用、独立 session 与数据迁移能力，再完成模块与既有流程接入，最后做整体客观验证。这里先定义测试清单，不以主观体验评估阻塞需求整理，也不在本轮启动实现或运行模型测试。

| 测试域 | 客观断言 |
| --- | --- |
| 分类开关 | 关闭不创建/调用分类 session，按是否必须 @选择普通流程；启用后每条合格新消息只分类一次，放行不绕过必须 @ |
| 分类 `no/no/yes` | 前两条不启动主 loop；第三条放行后，主模型收到三条源消息，且无分类内容 |
| context 隔离 | 不同群/私聊分类上下文不串；主模型输入没有分类提示、推理和结果文本 |
| 消息完整性 | 连续多条 `no`、异步新消息、超时、重启或投递失败不导致静默丢消息、重复入账或错误推进游标 |
| 接入与权限 | 未授权消息不进入模型；分类不能改变权限；好感 100 不新获历史查询资格 |
| 冷落开关 | 分别关闭三类规则，不产生对应变化；重开不补罚关闭时段 |
| 等待回应 | 发送失败不开始等待；同一等待只触发规定次数；回复/睡眠按规则结束或暂停 |
| 断联日结 | 5 天封顶、第五天额外扣分、10 天冷却、40 下限、特殊关系豁免，严格按最终定义执行 |
| 原值低于下限 | 原好感低于 40 时，衰减逻辑不把它抬到 40 |
| 情绪额度 | 单次/窗口/一级联动/满足上限按定义执行，不靠升降抵销绕过额度，不递归联动 |
| 满值与解除 | 锁定不阻断解除检查；自然到期、帮助解除、减半和超时影响均有唯一结果 |
| 睡眠状态机 | 入睡、唤醒、再睡、深睡、顺延和午睡条件可达；消息接收和起床计时不被“停止计算”一并停掉 |
| 主动与求助 | 一次转移不重复联系；超时/跨日中止；发送失败与未回应分别记录；错过机会不连补 |
| 真实夜间消息 | 按定义保留与交付，摘要阈值不变成静默删除；不混入过期主动意图 |
| 好感归因 | 甲的事件不改乙账目；制造者不能领取被禁止的解决奖励；求助未回应不经间接链路扣分 |
| 时间与重启 | 回拨无负时长，跨日无重复结算；保存后重启恢复状态、额度、流程与去重信息 |
| 持久化故障 | 不可写、损坏、提交中断不发布虚假成功或静默重置；同目录双写被拒绝 |
| 查询与历史 | 显示方向、舍入和阈值一致；峰值与末值不混淆；历史空缺不补造；他人私聊原因不泄露 |
| 确定性 | 相同初始状态、配置、归一化事件和有效时间序列得出相同数值与状态转移 |

分类器语义准确率可以用用户明确标注的样本单独记录；自动流程测试使用固定分类输出，不能把模型随机回答当作状态机的判定基准。不要求重跑模型逐字一致。

“像不像真人”“语气够不够亲近”“数值速度是否讨喜”等由用户自测反馈，反馈后再调整参数与表达策略。测试不替用户判断主观好坏。

## 9. 剩余定义工作

主要待补项已集中在[参数清单](emotion-system-parameters.md)：

- 原文没有给出数值的阈值、速率、冷却、限频、函数和优先级。
- 前置分类器启用范围、默认开关、session 生命周期、上下文容量与失败后任务处置。
- 六欲渠道和记忆重要度的宿主接入接口。
- 旧好感文件与特殊关系的实际维护方式。
- 心愿“每日至多一件”与“每日一至数件”、原文各时间规则之间的口径统一。

成本、延迟、是否具有心理学依据及主观自然程度不列为功能需求的否决条件。
