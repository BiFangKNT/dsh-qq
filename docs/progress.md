## 工具收尾范围

本批处理已经核查的工具返回问题，遵循[工具设计规范](tool-design.md)。不重写全部工具，不新增功能开关，不改变既定访问权限、记忆职责或实时图片屏蔽与历史取图的区别。

| 范围 | 要完成的行为 | 验收重点 |
| --- | --- | --- |
| 执行失败 | 戳一戳、表态、点赞、取图、发送、撤回和收藏等工具不再用普通成功结果承载执行失败；保留简短且可行动的原因 | 通过本地宿主原生执行器确认失败标记进入模型续调；正常空结果不误判为失败 |
| 外部操作状态 | 区分已确认、明确拒绝、尚未发送和结果未知；图片、表情等出口不把超时说成“没发出去”，`qq_mface` 未确认时不自动换 CDN 重发 | 回执缺失、超时、断线与明确拒绝分别验证；结果未知不自动重试、不推进成功记账，现有文字与语音语义保持一致 |
| 列表与长结果 | `qq_faces` 补齐真实总数、局部标记与翻页；`qq_memory` 的列表和版本历史可分页或续读；`qq_history` 按完整序列化结果控制返回总量 | 元数据与 JSON 转义计入预算，长条目可继续读取，分页无重复遗漏，不悄悄改写原文 |
| 简短返回 | 清理 `qq_search` 的固定免责声明与续读教程、取图的重复打开提示、发送的固定重试说明，以及表情收藏和限流返回中的说教 | 固定规则移至工具说明和参数定义；保留本次错误原因、未确认状态、等待时间、来源和继续读取所需字段 |

不为统一形式把所有结果压成同一种对象或给所有失败强加错误码。只调整存在问题的返回与必要的公共出口，保留现有工具名；工具说明、结果渲染与相关文档同步更新。

先运行针对失败、未确认及分页边界的专项测试，再验证未修改的本地宿主组件和 mock 消息链路，最后跑全套与 mock E2E。验证客观逻辑，不以模型措辞是否自然为通过条件；实际覆盖与结果仍只记录在 [TESTING.md](../TESTING.md)。
