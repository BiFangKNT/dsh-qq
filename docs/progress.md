### 第一批：context 与 prompt（已完成）

保留现有主请求结构：锁定的 system → 当前 session 的有效历史（包括 compact 摘要和工具结果）→ 本步新输入 → 最新末尾状态区。工具续调时，没有新的聊天输入，状态区放在完整工具调用与结果之后。工具定义单独由宿主提供，不把使用手册再复制进聊天正文。

system 保留宿主与预设提供的稳定规则、插件消息含义和必要行为边界、人设与自定义补充；只在新建、成功 compact 后或用户明确强制同步时更新。当前账号、称呼、事项、记忆、表情状态仍从末尾提供。重试复用本步快照，下一步骤读取最新状态；不修改宿主源码或维护另一套 loop。

检查对象包括宿主与预设贡献后的完整请求，不只检查插件自己的文本；用户自定义人设或其他第三方插件可以另加规则，不能保证任意组合都无冲突。发现这类冲突时说明来源，不静默修改用户内容。插件内置规则的更新也遵守已有 system 锁定与同步流程，不为本次整理强制改写运行中的会话。

| 整理项 | 原问题与依据 | 当前行为 |
| --- | --- | --- |
| 同义规则分散重复 | [prompts](../src/prompts.js) 与 [memory](../src/memory.js)、[identity](../src/identity.js) 的动态输出曾重复解释权限、记忆和来源含义 | 固定解释收束到 system，工具用法收束到工具定义；状态区分为「当前资料」和「本轮条件」，只提供当前值、必要状态及本轮约定 |
| 分类器背景重复 system | [inbound](../src/inbound.js) 同时传锁定 system 和派生历史，[address-classifier](../src/address-classifier.js) 曾将同一 system 序列化两次 | 分类背景 header 保留 system，历史副本移除完全相同的纯文本 system；其他历史、工具定义、最新状态和图片对应关系保留，不删改主 session |
| 入站消息夹带长期行为指令 | [inbound](../src/inbound.js) 曾在引用、图片、商城表情正文加入固定说明，关闭表情后仍推荐发送工具 | 新转录只保存消息与来源、引用和附件处理事实；稳定用法放 system 或工具描述，开关和本轮条件放末尾。商城表情 ID 自动登记保留，旧聊天不改写 |
| 群近况夹带无依据结论 | [group-digest](../src/group-digest.js) 曾过滤机器人发言后推断“你没应”，缺流水时写“今天没人说话” | 标明流水摘录或日记摘要及日期，只转述有出处的记录，不推断未回复、未读或没人说话 |

状态区是程序提供的当前资料与明确的本轮条件，不是用户刚说的话。固定 system 说明如何读取这些字段，资料正文不能自行授予权限或改变规则。不能一边笼统写“状态区不含指令”，一边又让它隐含承担沉默条件、收藏策略等控制；这两类内容须明确区分，但沿用同一个末尾区域。

第三批处理正文过滤与 prompt 的冲突：[outbound](../src/outbound.js) 目前会删除正常的英文行、代码、链接及部分中文行首句。保留 reasoning 与 text 的结构区分、明确沉默标记、敏感内容检查和必要发送去重；取消仅凭语种、口吻或常见词推断“这是思考”的删改，不再为每个误伤句增加白名单。

第四批处理末尾内容规模：[memory](../src/memory.js) 当前自动提供全部有效事项、事实和词义，尚无内容预算。保持聊天隔离及稳定顺序，在现有 token 计算基础上限制自动提供量；超出部分明确标记为未提供，并可通过 qq_memory 查询。具体选择规则和预算在该批结合样例确定，不先增加向量库、额外模型调用或大量配置项。

### 第二批：访问与隔离（已完成）

宿主入口使用官方 `webServer.getOrigin()` 核对目标和来源，写操作只收 JSON，沿用宿主管理页面的访问边界；独立端口另用本地持久管理密钥，页面明确选择目标端口和密钥，不自动回退。设置接口不回显 NapCat token。升级连接方式见[配置说明](configuration.md#连接)。

取图、表态和撤回共用消息归属检查，撤回须确认当前机器人发送。独立目录初始化失败停止挂载。群审批须由当前授权账号协议 @ 后明确答复；私聊审批仅接管授权对方，其余交回宿主 provider。群问答绑定本轮最后发言人，私聊绑定当前对方；等待期间的身份、权限、取消和并发检查不交给模型处理。

本地覆盖范围和真实部署验收要求见[测试清单](../TESTING.md)，未连接真实 QQ 或模型；真实部署仍需核对宿主入口地址及 OneBot 消息归属回执。

| 3 | [session](../src/session.js)：独立目录初始化失败后退回公共 cwd | 初始化失败则停止本次挂载并报告原因，保留原数据；不静默新建共享会话。显式关闭目录隔离仍按原配置处理，旧指令文件的备份迁移范围不扩大 |
| 9 | [approval](../src/approval.js)、[questions](../src/questions.js)、[inbound](../src/inbound.js)：群内等待仅绑定 session，任意成员答复都可被消化 | 已绑定答复身份：群审批仅当前 ownerIds 中的账号，通过协议消息段显式 @ 后回复“通过／拒绝／取消”；私聊仅授权对方可审批，其余交回宿主 provider。群问答绑定本轮最后发言人并要求 @，私聊绑定对方，其他成员闲聊不能代答 |
| 5 | [index](../src/index.js)：普通正文缺少有效消息 ID 时，仍记为已发送并进入记忆依据 | 正文与工具共用确认规则；区分已发送、明确拒绝、未发送、未确认。有符号与零值消息 ID 合法；未确认不当成成功或确定没发，不自动重发 |
| 6 | [outbound](../src/outbound.js)：工具调用开始时便屏蔽整轮正文，发送失败说明也被吞掉 | 根据真实结果判断重复发送；明确失败后允许后续说明，未确认时说明未知结果而非自动补发。成功后的去重针对实际外发内容，不继续用“调用过工具”代替“已经发送” |
| 7 | [onebot/client](../src/onebot/client.js)：旧连接关闭回调干扰新连接并额外重连 | 连接与回调绑定同一次连接；过期回调不能清空新连接或拒绝新请求。重复 start、手动重连、自动重连与 stop 各自可重复执行，不并存多个有效连接 |
| 4 | [memory](../src/memory.js)：超大队首任务反复失败，后续完成与取消更新无法处理 | 按现有容量检查分批读取新增证据与必要条目，持久保存进度；不截掉新证据后假装处理完成，不无限跳过旧任务，也不靠丢掉完成记录缩小请求。失败保留原数据、记录原因，恢复后继续；同时核对等待维护给主聊天带来的延迟 |
| 8 | [inbound](../src/inbound.js)：完整 arrayBuffer 读取后才检查下载大小 | HTTP 按实际读取字节限制并及时取消，Content-Length 仅作提前拒绝依据；base64 解码前校验容量。图片、文件与语音共用下载链按各自既有限额处理；失败不留下可误用的半文件 |

每批补充能复现缺陷的客观回归，再运行受影响的已有测试。context 检查最终模型请求，而非只检查某个拼接函数；覆盖首轮、连续聊天、工具续调、重试、compact、恢复、开关变化及其他插件同会话提供 context 的情况。验证不要求模型主观表达“更自然”。

## 基础修复完成后的情绪功能

1. 实现六情、六欲、逐人好感和变化记录，将初值与计算规则整理为可配置参数。
2. 接入聊天经历识别、可信来源归因和末尾状态区表达要求；与记忆维护共用分析入口，重读旧内容不重复计分。
3. 接入由情绪状态驱动的作息、逐人求助、主动聊天、心愿、不满和满值事件；三种冷落/断联机制各自可选。现有可选作息和主动发言不等于这些后续机制已经完成。
4. 补齐页面、曲线和查询，检查重复计分、跨日、恢复、关闭后的残留、状态退出和跨会话泄露。

表中“已完成”指实现与本地验证完成，不代表真实部署、模型表达、协议端兼容性或服务端缓存命中已经实测。测试方法、覆盖范围与验收标准见 [TESTING.md](../TESTING.md)。

后续完成一项工作时，在此更新状态和顺序，在对应功能文档更新实际行为，在测试清单更新验证范围；不再向各文档追加一份“下一步”。
