# 情绪系统：设计与接入

以[需求简版](emotion-system-overview.md)为功能范围，详细参数见[参数清单](emotion-system-parameters.md)。本文维护情绪功能的设计与接入约束，当前进度和开发顺序统一见[开发进度与计划](progress.md#当前进度与下一步)。

记忆行为见[记忆整理方案](memory-design.md)，宿主接入见[末尾状态区](host-transient-context.md)，消息保存和容量处理见[群消息设计](group-message-design.md)。

## 代码怎样安排

沿用现有插件、主会话、作息和主动消息入口，不增加独立服务。

| 部分 | 负责什么 | 实现安排 |
| --- | --- | --- |
| 消息判断 | 是否在和机器人说话；保留暂时不回复的消息 | 独立调用模型、独立保存记录，已接入 |
| 情绪与关系 | 根据经历和时间计算六情、六欲、好感，保存变化原因 | 新增少量内部模块；程序计算数值，模型只识别经历 |
| 作息与主动行为 | 睡眠、唤醒、逐人求助、日常开口、心愿与不满记录 | 扩展现有 `sleep.js`、`wake.js`，由同一份状态决定行为 |
| 表达与查看 | 回复前提供当前说话要求；页面和对话查询 | 每次请求末尾提供一份当前状态，动态更新、不保留旧快照；按权限提供原因 |

同一机器人共用心情，按联系人分别记录关系。跨聊天只传当前表达要求，不传其他聊天的人物、原话、时间和事件原因。动态好感另存，不覆盖旧 `affinity.json`，也不增加管理权限；历史查询已与好感度脱钩。

情绪计算先按时间推进，再处理一次经历；重复消息不重复计分。锁定、求助和睡眠都有明确的进入、退出条件；关闭某个机制时停止它的后续作用，不补算关闭期间的惩罚。缺失参数采用原文初值或在对应功能开发时确定，并记录在参数文件中。

## 固定提示词与动态状态

固定提示词沿用现有 system 快照与同步流程；动态情绪、对当前发言人的好感和表达要求放在请求末尾状态区，每步读取最新状态，不把旧快照交给 compact。情绪接入不另建提示词同步机制。具体行为见[配置与同步](configuration.md#上下文--人设--记忆)、[状态区接入](host-transient-context.md)和[状态区内容](memory-design.md#读取方式统一末尾状态区)。

框架定义统一维护在 `src/prompts.js`，不写入聊天工作目录的 `AGENTS.md`。旧模板只在确认归属后备份、停用，手改内容保留；见[迁移说明](configuration.md#工作目录指令与升级)。授权账号与成员称呼独立，情绪好感不能增加权限或改变消息顺序，见[人设与称呼](persona.md)。

## 可选的消息判断

本节描述分类器行为。群聊“必须 @”是硬限制，分类器不能绕过；群聊等待和配置迁移见[触发规则](group-message-design.md#2-群聊什么时候处理消息)。消息保存和容量处理由[群消息设计](group-message-design.md)统一说明。

- 默认关闭；群聊与私聊共用一个开关。开启后判断是否在对机器人说话；群聊要求 @ 时，须自身 @ 且判断为 yes 才触发主模型。
- 仍遵循群/私聊访问控制、同类机器人开关、连聊上限、作息与安静轮。审批和问答回复走原控制通道，不等待分类模型。
- 每个机器人身份、每个群/私聊单独保存判断记录，并使用独立的模型 session ID 和判断提示词，不挂载主会话工具。主会话的提示、工具说明及聊天内容仅作为判断背景，不作为分类器指令。
- 判断输入只读主 session 当前有效的聊天内容及已记录的系统提示、工具说明，使用 DSH 的 `deriveMessages()`，压缩后不读被替换的旧历史。另附尚未进入主 loop 的已准备消息和当前消息的来源、正文、引用与附件。容量允许时完整提供；超预算则仅对分类器输入左截断并标明缺失、移除对应图片，不压缩主会话、不切断工具调用与结果。
- 分类为 `no` 或暂存时，不修改主会话 system 和历史，也不触发主会话换代。分类器读取已锁定的 system 快照；旧便签与一次性交接注入已经退役。审批快速通道同样遵循同类机器人开关。
- `no` 保留消息；`yes` 在当前 @、权限、作息等条件满足时，按顺序提供截至该消息尚未交付的正文。不以 30 条为限，但须通过总容量检查；装不下的旧范围明确记为“未提供”，不会冒充已读。主会话图片、文件仍走原媒体处理及屏蔽规则。
- 分类器支持实际图片输入：主会话已有图片、待交付图片和当前图片按来源附带，使用宿主 `attachments` 保存的图片引用，不把 URL 或路径当成看图。分类器不受成员图片屏蔽限制；被屏蔽图片不写入主会话缓存，也不将仅供分类的图片引用带入主会话。需要支持图片的分类模型；下载、入库或能力检查失败明确记录错误并保留消息，不偷偷改成纯文本判断。单条沿用前 4 张和 `imageMaxMB` 限制，格式及总大小还受宿主附件服务限制。
- 先严格解析 `yes/no`，失败再从回答正文正则提取独立的 `yes` 或 `no`；两者同时出现视为无法识别。不从推理内容提取。仍无法识别时额外请求两次，三次均无法识别则按 `yes` 放行；不自动换模型。超时、网络及配置错误仍记录失败并保留消息，关闭或卸载不触发兜底。
- 沿用按天落盘的插件日志：重试记录 `warn`，正则成功记录 `info`，最后的兜底明确记录 `warn` 和 `fallback_yes`，包含分类 session、会话、源消息 ID、provider、model、请求次数和原因，不记录分类回答原文或推理。消息记录也保存实际解析方式和请求次数。
- 主模型忙碌时继续分类，正文先保存；空闲后再交付。私聊仍按 `mergeWindowMs` 等待合并，恢复检查约每秒一次。
- 睡眠或回复间隔阻止交付时，待处理消息留在本地；醒来、间隔结束或插件重启后恢复已放行的消息。新收到的后续 `no` 不会被之前的 `yes` 顺带放行。
- 关闭后不再发起分类请求：群聊按当前触发设置处理；私聊未交付消息按顺序转入普通处理，新消息不越过旧队列。不同账号不能恢复彼此的记录。

实现入口为 `src/address-classifier.js` 与 `src/inbound.js`；设置页、配置定义和覆盖白名单已接通。

### 保存与边界

普通消息与分类器共用 `messages.sqlite`，源事件、准备后的正文、判断结果及交付状态分别保存；分类结果不代替主会话接纳或完成证据。恢复、去重、旧记录迁移和附件保留统一遵循[消息保存与容量边界](group-message-design.md#第-3-批实际实现)，不在分类器内再维护一套处理位置。

分类器看图另存宿主附件引用，不以内联 base64 重复写入正文。重启后可继续附带已有引用；旧格式中没有引用的已准备记录不会自动重新下载。关闭分类器后停止判断请求，尚未交付的范围按当前普通触发规则处理。

## 与记忆维护的接合

后续接入情绪时，记忆维护与情绪经历识别共用一次分析入口，状态和计分分别保存。模型识别经历与可信来源，程序负责计算数值；重读旧记忆、compact、换 session 和维护重试都不重新触发经历。开发顺序统一见[当前进度与下一步](progress.md#当前进度与下一步)，不在本文另列待办。

验证范围与待实测项目统一见 [TESTING.md](../TESTING.md)。
