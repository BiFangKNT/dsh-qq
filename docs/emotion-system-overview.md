# 情绪系统：需求简版

这份文档作为接下来的讨论入口。先说清楚她会怎样表现，具体数值和代码安排以后再定。原有功能都保留，不用开发先后决定需求是否成立。

## 1. 我们想做出什么

让她有持续的心情、自己的需求，以及对不同人的长期态度。这些会随聊天和时间变化，并影响她怎么说话、什么时候主动做事。

例如：被连续冒犯后，她会生气一阵子；得到安慰后会缓过来。与某个人长期相处，关系会慢慢改变，不因为一两句话就彻底翻转。

## 2. 她需要记住什么

| 记住的内容 | 用来做什么 |
| --- | --- |
| 当前心情：喜、怒、哀、惧、爱、恶，以及原文的“欲” | 决定这段时间说话的情绪色彩 |
| 当前需求：食欲、睡欲、触欲、声欲、色欲、求知欲 | 决定她想做什么，是否需要找人陪伴或帮助 |
| 与每个人的好感，以及谁造成了影响、谁提供了帮助 | 决定长期的亲疏态度，避免把事情算到无关的人头上 |

心情是全局的，好感按人分别记录。她可以因为一件事心情不好，但不能因此降低对所有人的好感，也不能向别人泄露这件事的私密内容。

## 3. 她会有哪些表现

**聊天会影响心情。** 被夸、被冒犯、被哄，或者在意的人受到攻击，都会产生相应影响。连续发生的事情影响可以累积，停止后逐渐恢复；特别强烈时，可以需要安慰或更多时间才能缓过来。

**需求会变化，也能得到满足。** 陪伴、睡眠、阅读、音乐、亲密交流等可以满足不同需求。她自己接触的内容也可以影响她，不必所有变化都来自别人。

**她会有自己的作息。** 会困、准备睡觉、被叫醒、再睡和起床，也可以午睡或答应陪伴到某个时间。睡着时收到的真实消息留下来，醒后处理；错过的主动开口机会不一条条补发。

**她会主动做事。** 可以主动聊天、找亲近的人求助，也可以有每天想做的事。求助时可以按顺序换人；普通主动聊天没人回应时先暂停。求助没有解决，可以留下简短记录，之后在合适的话题中表达。

**关系会慢慢变化。** 某个人带来的愉快、伤害和帮助，影响她对这个人的长期态度。越亲近，说话可以越亲近；关系较远时仍保持礼貌。好感不会改变这个人的管理权限。

## 4. 哪些行为可以关闭

以下功能可以选择是否启用：

- **先判断是不是在和她说话。** 使用独立会话判断；不是就暂不回答，消息仍然保留，下次需要回答时一起提供。判断过程不混入正式聊天，推理强度默认 `low`，可以修改。
- **长时间没人互动，心情逐渐低落。**
- **发出消息后一直等不到回应，感到被冷落。**
- **与某个人长期不联系，好感逐渐下降。**

后三项分别处理，不用一个开关或同一个等待时长把它们混在一起。先明确是否启用，具体多久、变化多少放到后面定。

## 5. 我们怎样看见和检查效果

页面能查看当前心情、需求、好感、变化曲线，以及变化的大致原因；对话中也能按权限查询。她记下重要经历时，可以根据当时的情绪调整重视程度。

程序测试检查算错、重复扣分、消息丢失、睡后醒不过来、关闭后仍然生效等逻辑问题。她的表现是否自然、数值变化是否合适，由用户实际使用后反馈。

## 6. 实现先守住一个简单思路

程序负责记住这些情况，按照聊天和时间更新；模型根据更新后的情况组织回复。作息、主动联系和消息发送沿用现有项目继续扩展，由一处统一处理。

这一步先把上述行为讲通。模块怎么拆、文件怎么存、每次增减几分，等进入对应功能的开发时再决定；已有详细材料留作查阅，不作为当前讨论清单。
