# DSH 末尾状态区接入

已验证版本为 DSH **0.2.2-rc.2**。直接使用官方发布包，不修改宿主、不安装补丁，也不替换 agent-loop。安装要求为 `>=0.2.2-rc.2`；运行时核对 agent、agent-loop、llm、session、session-projection、system-prompt 六个包。测试依赖仍固定 rc.2，保证回归可复现。

## 版本确认

版本未经验证时仅保留设置界面和设置接口，不启动 QQ 连接、主动消息与会话维护。浏览器通过官方全局弹层和 `RiskConfirmation` 显示当前版本、已验证版本及风险；取消或关闭保持暂停，设置页可重新打开。勾选了解风险后才能确认，确认结果保存到插件的 `settings.json`，不修改宿主文件。

确认保存为 `acceptedDshVersions` 对象，键是六个完整包名、值是各自版本号。版本变化后旧确认自动失效；接口拒绝提交已过期的版本确认。只跳过版本限制，缺少 `session.append`、会话投影或提示词接口仍会报错。

桌面 `uiOnly` 与 QQ 运行端分进程时，设置页读取同一插件家目录内运行端发布的 `host-compatibility.json`，确认后由运行端的配置热加载启用 QQ。运行端尚未发布记录时等待，不用设置端版本代替。运行端离线时文件是上次记录，确认不等于启动成功；运行端重启仍会按真实版本重新核对。同一插件家目录应只对应一个 QQ 运行端，多实例需各自隔离 `DSH_HOME`。

没有浏览器界面的部署可以把 `host-compatibility.json` 中的完整 `versions` 对象复制到 `settings.json` 的 `acceptedDshVersions` 字段，明确接受对应版本的风险。支持热加载，无需改动宿主。QQ 初始化报错时设置页显示原因，修复后重启运行端，不自动重复部分完成的初始化。

## 请求和清理

QQ 会话通过官方 `systemPrompt.context()` 提供当前状态。每个被接纳的模型步骤捕获一次资料；普通请求重试复用该快照，工具续调重新捕获。资料作为 user 角色的 runtime-context 快照出现在聊天和工具结果之后，不改变锁定的 system。

响应提交后、工具执行前，插件通过 `session.append()` 的 `surfaceOp: { op: 'replace', ... }` 将本次状态快照替换成空 developer 节点。官方派生模型输入时忽略空节点，因此下一次请求与 compact 不包含旧状态。原快照与替换事件保存在日志中，能够回放请求依据；这不等于从磁盘删除历史快照。

会话投影记录仍有效的状态节点、system 节点及压缩位置，避免逐请求扫描整份日志。重复安装只注册一次；没有待清理节点时清理是无操作，不新增日志。恢复会话先清理遗留节点，之后才发布 agent。中断或请求失败后在空闲边界清理；超窗错误在官方恢复压缩之前清理。

system 在压缩后的首次组装时同步。官方自动压缩及超窗恢复可能发生在本步骤 system 已组装之后，此时本步骤与重试仍沿用已接纳的 system，下一步骤才同步新配置。手动压缩后的设置同步操作会立即重新组装 system。

官方把同一会话各插件的 runtime-context 合成一条快照，所以清理对象是**包含 QQ 状态的整条快照**。同一 QQ 会话中的其他运行时资料会随下一步骤重新提供；没有 QQ 状态的快照与普通 agent 不受影响。不改写已经构建或冻结的请求，不注册新 session 事件类型，不改工具调用或工具结果。

清理失败会被记录，并阻止后续该 QQ 会话的模型请求；压缩请求若仍携带 QQ 快照会被拒绝，不能把它交给摘要模型。正常读写对话中已经出现的事实、事项及工具结果仍然参与压缩。

## 缓存、性能和升级

没有新增模型调用或网络往返。每步骤会增加状态快照及清理记录；日志随步骤增加，空节点在后续 compact 时可被一并收束。替换导致官方重新派生模型历史，成本随当前会话规模增长。旧状态位置之后的提示缓存允许失效，真实缓存命中与延迟必须在部署环境测量。

本方案依赖当前官方版本的快照恢复、响应结束事件、空节点派生、重试与压缩顺序。使用公开接口不代表自动兼容后续版本；只有通过契约测试才列为已验证版本。版本号检查读取插件解析到的包，不能识别同版本被私自修改的文件，也不能识别宿主另外加载的重复包。

`pnpm-workspace.yaml` 仅为本地回归使用的 DSH `0.2.2-rc.2` 包列出新包等待期例外，便于 pnpm 12 在该版本刚发布时安装；没有关闭其他依赖的等待期检查，也不扩大允许的版本。

## 验证

`node test/run-all.mjs host-transient-context` 运行未修改的真实官方循环、工具执行、会话投影、token 计量、compact 与 JSONL 持久化，仅模型适配器返回固定响应。覆盖最新状态、重复挂载/清理、重试、工具续调、普通会话隔离、同会话其他动态资料、手动/自动/超窗压缩、落盘恢复、清理写入失败及中断。

自动记忆维护与迁移使用 `node test/run-all.mjs memory`，完整模拟管线使用 `pnpm test:e2e`。这些检查不连接真实 QQ 或模型，不证明已部署、服务端缓存命中或模型语义效果。
