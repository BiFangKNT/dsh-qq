# 工具设计规范

适用于本项目新增或修改的模型工具。目标是让模型知道工具怎么用，并用尽量少的上下文准确表达本次执行结果。

## 说明与返回各写什么

**固定规则写在工具说明和参数定义中，本次事实写在返回中。**

- 工具说明写用途、适用范围、重要限制、返回字段或错误标识的含义，以及模型收到这些结果后应如何处理。
- 参数定义写字段含义、必填条件、默认值和合法范围，不在每次返回中重复使用教程。
- 返回只保留本次数据、执行状态和下一步必需的信息，例如来源、版本、续读位置、失败原因或重试等待时间。不重复固定警告、免责声明、权限规则和操作说明。

简短不能牺牲准确性。部分返回、结果未确认、可能已经执行等区别必须明确，不能都简写成“成功”“失败”或空结果。只在特定情况下成立的信息，也不能提前写成工具的一般规则。

## 成功、失败与续读

- **成功**：返回任务需要的数据和必要标识；无须再解释工具具有什么能力。
- **失败**：使用宿主的工具失败通道，不把失败伪装成成功数据。已在说明中定义的常见失败可只返回简短、稳定的标识；未预定义的问题给出简短且可行动的原因，不为省字全部归成“未知错误”。详细诊断留在运行端日志，避免泄露凭据和私有路径。
- **局部结果**：明确标记内容不完整，并提供继续读取所需的位置或标识；续读方法写在工具说明中，不随每页重复。
- **外部操作结果不明**：保留“未确认”状态，不能声称成功或未执行。是否允许重试写在工具说明中，程序按实际能力限制，避免重复发送等副作用。

返回长度限制应包含元数据和序列化转义后的完整结果。达到限制时明确提供局部结果或分页，不悄悄改写原文，也不把截断内容当成完整内容。

## 示例：原文定位失效

`qq_search` 的工具说明定义：`STALE_REFERENCE` 表示本次定位或版本已失效，没有返回正文；不能声称已读到最新原文，需要重新搜索后再读取。

发生时只返回工具错误 `STALE_REFERENCE`，不附带整段处理说明。该错误只说明本次读取失败，不改写历史结果，也不推断旧版本的全部内容都是错误的。

## 实现与维护

工具说明是模型的使用约定，不能代替程序检查权限、参数和执行条件。错误标识、字段含义或处理方式发生变化时，同步更新说明与相关测试。测试验证实际状态、数据和失败边界，不判断模型主观上是否“理解得好”。

本规范用于后续新增和修改；现有工具结合各自改动逐步调整，不因此无关地批量改写全部工具。
